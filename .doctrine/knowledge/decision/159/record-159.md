# DEC-159: Phase refinement is consumed; only stable identity is bound

**REQ-449 criterion 4 is built here.** The scope names it — subset validation over normalized typed values, never source text — so the monotonic-restriction algebra is a pure function over typed values, per the project's pure/imperative split. The rest of the work contract is not built: phase criteria, worker instructions, and everything launch and harvest require are Non-Goals with no consumer in this slice.

**The algebra has a real caller.** The provisioning verb accepts an optional phase-refinement document by path, applies the algebra to the resolved base policy, and binds the refined policy into the transaction or refuses. An algebra whose only caller is its own test certifies a path production never takes — the objection DEC-156 raised against a test-only execution path, and it bites hardest on criterion 4's refusal branches. The later launch slice replaces the file input with a programmatic one and leaves the algebra untouched.

**The refinement document reuses the `[interpretation]` schema.** Subset validation then compares like with like through one parser. This is DRY on a genuine invariant, not the reflexive kind: the two documents describe the same typed values and are obliged to change together — the shared referent DEC-155 found absent in the bubblewrap flag names and present here.

**The transaction binds only what has a consumer now:** the accepted base OID, the canonical policy hash, the refined policy or none, the capsule identity, the resource choices read from `[capsule]`, and phase identity. Later slices add fields rather than rework them. This set is also what REQ-450's freshness evidence and the later harvest and admission work attach to.

**Phase identity is bound; plan schema is not.** RFC-027 (open) proposes reshaping selectors, plans, phase gates, and criteria, so the transaction carries phase identity only as a durable reference — the slice id and the immutable `PHASE-NN` — and nothing of `plan.toml` or the phase sheets. Provisioning reads neither: the refinement arrives as its own document in the `[interpretation]` schema. Everything criteria-bearing, which is where RFC-027's churn lands, therefore stays with the later launch slice by construction rather than by intention, and this slice's cost under that reshaping is one stable reference field.
