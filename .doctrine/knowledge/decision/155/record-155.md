# DEC-155: Capsule confinement profile stands alone from the worktree jail

The capsule confinement profile is built in `doctrine-control`, self-contained: its own bubblewrap flag constants, its own profile builder, and no import from `src/worktree/`. `bwrap_core_argv` (`src/worktree/jail.rs:537`) is not widened.

**It is *a* backend, not *the* profile.** SPEC-030's platform backend contract is stated in observable properties with no mechanism named, and REQ-459 criterion 3 admits any backend that passes the property suite independently — so bubblewrap is one implementation among several that will exist. Landlock supplementation on non-NixOS Linux, Docker, LXC, and virtual machines are all backends on platforms doctrine already supports, none of them decided against. Module, type, and constant naming is therefore plural-ready from the start: this is the bubblewrap backend beneath the contract DEC-156 defines, never a singular "the confinement profile" that a second mechanism would have to be grafted into. The self-containment decided here serves that directly — a backend coupled to `src/worktree/jail.rs` would make the second implementation harder, not easier.

**Why not one builder.** The two profiles differ on every structural axis rather than by options. Mount floor: `--ro-bind / /` against an allowlist. Namespaces: none unshared against `--unshare-all`. Network: default open with `--unshare-net` on opt-out, against default denied with `--share-net` on opt-in. Paths: the host path reproduced inside, against a fixed inner layout. Environment: inherited, against `--clearenv` plus explicit `--setenv`. Session: absent, against `--new-session`. There is no assembly logic in common. `bwrap_core_argv` is additionally a fixed vector asserted byte-equivalent to `scripts/pi-spawn-confined.sh` (`jail.rs:1215`, SL-182 VT-7), so widening it in place fails the test whose purpose is to notice.

**Why not even the shared flag constants.** Seven of the capsule profile's twelve flag tokens also appear in the worktree arm. Sharing them was rejected: what DRY protects is an invariant — two sites obliged to change together — and there is none here. A bubblewrap flag is the spelling of a frozen third-party CLI, not a project decision; the two profiles have no obligation to agree, and a renamed flag would need independent re-review at each site because their meanings differ. The drift risk a shared constant guards is already covered better by REQ-459's suite, which runs a real bwrap and asserts the floor positively, so a mis-spelled flag refuses to start in the profile carrying it. Against that, importing the names would give the capsule backend a compile-time dependency on the module under the pi-spawn parity contract, and would assert a kinship between the two profiles that the axis-by-axis comparison disproves.

**Recorded departure from STD-001.** The standard's statement — when a constant for a value already exists, use it — reads against this decision. Its rationale, single point of change against silent drift, does not: that harm needs a shared referent, as `DOCTRINE_TOML` has and an external immutable vocabulary does not. The departure is recorded here so STD-001's review-time `VH` grep meets an adjudication instead of re-litigating it. The capsule module names all twelve of its flags once internally and is STD-001-clean within itself. Should the argument recur elsewhere it becomes a clarification to STD-001; one instance does not justify opening that.

**`have_bwrap` is restated, not shared.** `src/worktree/pretooluse.rs:314` is six lines of `PATH` scan, reachable only by publishing a PreToolUse-hook module — a worse trade than the six lines. It is also not the same question: the worktree arm asks whether bwrap is on `PATH`, while the capsule backend's admission question under REQ-459 is whether the host's backend passes the property suite, with presence merely a precondition of running it.

**Consequences.** The root lib's export set for `doctrine-control` shrinks to the git primitives and `DOCTRINE_TOML` — no bubblewrap surface crosses. `bwrap_core_argv` and its parity test are untouched, keeping risk R4 quiet and the incumbent suites green unchanged (R2). The capsule mount allowlist must be a declared input with a host-capability probe behind it (POL-002), never the spike's NixOS-shaped literals; its content is settled with REQ-459's suite, which has to assert the floor positively anyway.
