Refines DEC-358 and DEC-359 after RV-415 (F-3, F-4, F-6, F-8, F-10).

- **Pool size (F-3).** The BM25 pool is N = 50 entities, fixed and recorded with every run. N ≥ 25 keeps recall@25 reachable for A and the B arms; N ≤ 255 respects the Choice option cap. At N = 50 the B-list per-option cap is about 430–480 tokens over the measured queries, after an 80% packing headroom (replacing DEC-359's ~20 options at ~1.3k).
- **No id cue (F-4).** No option key or section prefix carries a canonical id: Choice option keys are opaque (`o1`, `o2`, …) and mapped back locally, and a section's prefix is title plus heading path only. A query can already cite a label by id, which BM25 does not index, so the headline is also reported over labels the query does not already name.
- **Matched-text control (F-6).** A sixth arm, B-point-matched, scores each pool entity with one Noul over exactly the option text B-list shows. B-list − B-point-matched isolates the ranker primitive; B-point − B-point-matched isolates the text and max-over-sections effect. The C-point→list − C-point delta is reported as a pipeline comparison, not a ranker one.
- **Batching agreement (F-8).** DEC-352's material-disagreement test: on one tuning slice's pool, batched point is kept iff Kendall τ between batched and section-as-state point scores is ≥ 0.8 and |Δ recall@10| ≤ 0.05; otherwise DEC-352's fallback applies (section-as-state, C on a 3–5 slice subsample).
- **Position bias (F-10).** Every list question is sent twice, forward and reversed; each option's probabilities are averaged and the order is taken from the mean. Order agreement between the two (Kendall τ) is reported per call as a diagnostic, not a gate.
