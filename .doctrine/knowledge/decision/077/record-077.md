SL-233 delivers the complete adoption path, not only the run engine:

- rewrite the active distributed `/design` skill as a thin bootstrap and
  recovery adapter;
- ship one small framework `stage/design` hymn containing the invariant
  managed-run operating contract;
- ship a small design-specific Markdown prompt pack selected by the current
  obligation; and
- have prompt projection compose the stable hymn, one selected process
  fragment, and the structured TurnEnvelope.

V1 targets the one orchestrating role and the normal best-available model
family. It does not create role/model variants or design user-override
semantics. Framework prompt content may therefore remain embedded and
authoritative.

Prefer a few coarse fragments over one fragment per transition or question.
Rust owns the closed obligation vocabulary and deterministic state semantics;
the operational prose behind stable obligation keys remains in Markdown so
routine process refinement does not require Rust changes. More granular
fragments are deferred until adherence, token-efficiency, or process evidence
justifies them.

The explicitly inactive `SKILL.compact.md` experiment is outside the delivered
contract.
