# DEC-158: Capacity is advisory, probed by statvfs, rooted outside the repository

**Mechanism.** The free-space probe is `rustix::fs::statvfs` (`rustix-1.1.4/src/fs/abs.rs:288`), available bytes computed as `f_bavail × f_frsize`. `rustix` is already a direct dependency at `default-features = false, features = ["fs"]` — added for `flock` in `src/worktree/claim_lock.rs` — so the probe adds zero compiled weight, and `Cargo.toml`'s existing "direct dep for nameability only" note is the precedent for recording it.

**POL-002 facet 3 lands on the unknown case, not on the syscall.** `statvfs` is platform ABI rather than a host tool, so it carries no capability declaration. Filesystems are diverse and not every field is meaningful on every one, so a probe that cannot produce a usable answer yields a distinct named *capacity-unknown* outcome that is reported rather than silently read as ample. Capacity is advisory under REQ-461, so unknown does not refuse provisioning either. The slice's real facet-3 declaration remains bubblewrap: feature-scoped, absent ⇒ failure naming what was missing and what would satisfy it.

**Config home: a new `[capsule]` table in `.doctrine/doctrine.toml`.** It must not ride `[interpretation]`, which is hashed and bound into the work contract (REQ-449, DEC-136) — an operational edit to a capacity threshold would otherwise change the canonical contract hash. It should not extend `[dispatch]` either: that is the incumbent worktree arm's config and this slice is additive beside it until the cutover slice, and the capsule programme will accrete further keys of its own.

**Two-tier semantics.** REQ-461 criterion 2 supplies the upper default — warn below twice the expected capsule size, reserving nothing. Criterion 3's halt is the lower tier: below one expected size, refuse to provision; between one and two, emit the conspicuous structured warning and proceed. A genuine out-of-space failure mid-provision halts identically. The expected size and the multiplier are both named constants (STD-001).

**Rollback of an incomplete provision is not eviction.** Criterion 3 forbids automated deletion of a capsule or result and the scope's Non-Goals forbid eviction; neither reaches a directory this call created before any transaction exists in it. It holds no work, and leaving it accumulates partial trees on a disk already short of space. Rollback is permitted, scoped so it can only target the path the failing call created. Anything wider is eviction and is out — and it is not a product-side delete verb (DEC-156).

**Capsule root default.** Not `${HOME}/capsules`: the spike's location is a host convention and POL-002 facet 1 forbids the product resting on one. Not the repository's runtime state tier either — capsules are large, and that tier is characterised as disposable scratch, which contradicts DEC-133 and DEC-137's holding that a harvested capsule is live work. The default is an owned path derived from the platform's data directory, outside the repository, overridable through `[capsule]`; where no location resolves, provisioning refuses with a message naming the config key rather than falling back silently.
