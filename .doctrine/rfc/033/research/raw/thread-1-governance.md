## Thread 1 — governance applicability

### Binding constraints

Grouped by the limb of the change each reaches. "Anchor" = the spec's `[[source]]` path or the ADR's prose-referenced path, `test -e`'d; ADRs carry no `[[source]]` blocks by schema (verified: `grep -rln '[[source]]' .doctrine/adr` → nothing), so an ADR's status is "prose-only" even when its code is live.

**(a) single source of truth for the shared conceptual corpus**

- **ADR-005** — the closest-binding artefact. It fixes the *tiering* by access pattern (push / pull-reference / skills) and three invariants the change must not break: "Single source per fact (DRY)"; "There is exactly **one** workflow doc (`routing-process.md`) — no parallel summary"; and the ratified restate line (R-OQ-4): a skill **MAY** name a verb and cite a rule by name, a skill **MUST NOT** reproduce flag syntax/option tables/storage mechanics as prose. It *constrains duplication* — it does not nominate a source. Anchor: prose-only; its §References cites `src/skills.rs`, which is **stale** (file gone; the skills embed lives at `src/install.rs:20`). That staleness is itself evidence the record was not maintained.
- **ADR-019** — Decision: "This is the one canonical vocabulary — descendants cite it unchanged", over the seven asset properties. A unified corpus that coined a parallel vocabulary for "source/derived/published" would violate this. Also position 3: projection boundaries follow volatility/trust/mutation-authority/consequence, and "standing governance and volatile project orientation must be physically distinct surfaces." Anchor: prose-only; §References cites `src/install.rs` (**live**) and the live memory key `mem.pattern.embed.rustembed-recompile-and-symlinks`.
- **SPEC-003** — the whole-system *context* spec: "It is a synthesis, not a description of any one container's mechanism" and it "holds the principles that hold across all containers … never restating any single container's mechanism." A cross-surface concept (entity engine, storage rule, core loop) that today lives on four surfaces belongs at this altitude, not in a new fifth surface. Anchor: **no `[[source]]` block** (it is a synthesis by design).
- **SPEC-018** — the worked precedent for "single source of truth": the relation vocabulary's source is the code-authoritative `RELATION_RULES` (`src/relation.rs`), "pointed at, never transcribed (storage rule)." Binds the *shape* of any source-of-truth nomination: owner in one machine-readable home, everything else points. Anchor: `src/relation.rs`, `src/relation_graph.rs` — **live**.
- **PRD-002 / the storage rule (SPEC-003)** — "structured obligations live as entities, narrative lives in the spec body, and the two never restate one another." Binds the format of whatever single source is nominated. Anchor: no `[[source]]`; the rule is carried by SPEC-004/SPEC-006.
- **ADR-024** — shipped-corpus grounding: every claim in a shipped asset must resolve on one of six client-resolvable forms; "A repo-private entity id or a repo-private source/spec path is never admissible, at any tier." If the unified corpus nominates a source, *how the other surfaces cite it* is already fixed by this. Anchor: prose-only; its §Verification cites the published address `reference/shipped-corpus-authoring.md` (live on disk as `install/shipped-corpus-authoring.md`).

**(b) unifying authoring format and information architecture**

- **ADR-005** — the IA rule itself: pull-reference docs must be *pointed-at* by a skill or boot ("shipping ≠ reachable"), exactly one workflow doc, no doc duplicates `doctrine --help`. Any re-IA must satisfy reachability and the restate line. Anchor: stale as above.
- **ADR-019 / SPEC-009** — physical roots follow semantic ownership, not the embed root; `install/` "ceases to own an asset merely because the binary embeds it." A format/IA unification that re-homes material across `install/`, `publication/`, `memory/`, `plugins/` is a root reorganisation governed here. Anchor: `src/install.rs` (**live**, SPEC-009 anchor); SPEC-009's declared sources are `src/install.rs`, `install/manifest.toml`, `src/root.rs` — all **live**.
- **SPEC-016 / SPEC-005 / SPEC-019 / SPEC-031** — per-kind render contracts (frontmatter-free Statement/Rationale/Scope/Verification/References for POL/STD; the analogous ADR, knowledge-record, and phase-plan content models). A "single authoring format" must not silently drift these. Anchors: SPEC-016 → `src/policy.rs`, `src/standard.rs`, `src/governance.rs` — **live**.
- **STD-001 / STD-002** — no magic strings (single-source named constants); short entity titles and "ids not slugs." Bind any shared format vocabulary and any title/slug renaming. Anchor: standards, prose-only by kind.
- **STD-003** — no silent skip; a degraded read is disclosed. Binds the enforcement mechanism (a doctor/currency check) that the census and SL-242 §Objective 4 both propose. Anchor: prose-only.
- **SPEC-011** — boot snapshot: the section/source taxonomy is declared in `boot_sequence` (`src/boot.rs:104-139`) — `Static("authority.md")`, `Static("routing-process.md")`, `CommandMap`, `Governance`, three `GovRows` arms, `Memories`, `Onboarding`, `Static("model-band.md")`, `ExecPath`. Changing what the boot *is* is a spec-and-code change, not an authoring choice. Anchor: `src/boot.rs` — **live**.

**(c) publishing reference material to a public web target**

- **ADR-019 (the `published` property) + SPEC-026 / PRD-017** — these are the only artefacts that define "published." ADR-019 defines it as "exposed for inspection/copy **through a declared seam**, without projection"; SPEC-026 makes the **publication manifest the sole authority** for what is public ("an asset absent from it is not published regardless of embed reachability"), read-only by construction ("The library never materializes"), licence declared per entry and **fail-closed** against the closed set **{MIT, GPL}**, with `doctrine library show reference/<name>.md` as the read seam. A personal blog is *not* that seam, and is a publish-*out* target while the library is read-only — so the change is governed by a model it does not fit. Anchors: SPEC-026's declared source is `src/search.rs` — **live**; the manifest mechanism lives at `src/publication.rs:1` (SPDX `GPL-3.0-only`), licence enum at `src/publication.rs:24-50`, and the completeness invariant `{install} − {base} ⊆ published` at `src/publication.rs:1009-1014` and `src/install.rs:1131-1139`.
- **Licence posture (RFC-021 §"Licence boundaries can surprise"; SPEC-026 D6)** — the engine is `GPL-3.0-only` (`Cargo.toml:6`); all of `install/` is MIT (`publication/manifest.toml:7,9-10`; `install/LICENSE`), so the *reference library* is freely republishable; the shipped memory corpus is **not** in the publication manifest and is not declared per-asset, and RFC-021 holds shipped process bodies to GPL (inferred — see Limits). A public target inherits this split.
- **POL-001** — clankspeak prohibited; binds copy tone on any public surface. Anchor: prose-only.
- **ADR-013 / ADR-014** — the change machinery: governance/spec change is staged and approved through a Revision (`REV-NNN`), and RFC "asserts no canon" — `RFC-033` is structurally absent from governance and confers no authority. Binds the *route*, not the content: resolving RFC-033 must land as a REV descending from the affected artefacts.

### Checked and not applicable

- **POL-002 (platform independence)** — does not reach the change. Its Scope: "Applies to all shipped doctrine behaviour — CLI, engine, MCP surface, gates, and any computed/enforced invariant. It does **not** constrain host projects' own choices: this repo may keep `(SL-NNN)` conventional commits, `just gate`, the edge/main split." A blog build toolchain or docs site is this repo's own outward-facing practice, not shipped product behaviour. It *would* bind if doctrine shipped a blog-export verb — then facet (3) requires the capability be declared, not silent.
- **POL-003 (harness independence)** — reaches harness wiring only (hooks, wire codecs, matchers, adapters); the learning corpus and its publication are not harness seams. Reason: scope clause enumerates hook registries, generated extensions, codecs, matcher sets. It is the *harness* axis of the same discipline POL-002 fixes for the *project* axis.
- **ADR-002 (global orientation memory class)** — governs the memory *mechanism* (the `repo=""` / `anchor_kind=none` / derived class, evergreen staleness), not corpus content or IA. The census's "no spec anchors `memory/`" is corroborated: `grep -rln 'identifier = "memory' .doctrine/spec` → nothing (positive control: the same grep idiom returns SPEC-010's `identifier = "plugins/"`).
- **ADR-011 (harness-agnostic spawn)** — orchestrator/worker spawn interface; no bearing on the corpus, format, or publication.
- **SPEC-023 / PRD-007's cascade** — governs *composable guidance* (hymn corpus, selector algebra, precedence, seal) and disclaims delivery placement; it is not the learning corpus's format authority. Binds only if the unification reaches `install/hymns/**` as an authoring format.
- **SPEC-025 / PRD-016 / SPEC-027 (web explorer)** — govern the *local* reading UI: loopback-only listener, graph/actionability/concept-map read models, `CatalogGraph` projection ("presentation-neutral", with two consumers). They do not govern a public target; PRD-016 is explicitly local-first. The `web/map` surface is applicable to the change's "web reading surface" limb but is silent on external publication.
- **SPEC-007 / PRD-004 (memory engine)** — owns the record/retrieve/scope/trust machinery and the onboarding class, not corpus content. It *is* load-bearing for one live mechanism the change must respect: `Onboarding` boot bodies are memory-body text of onboarding-tagged memories (`src/boot.rs:253-256`; `memory::onboarding_bodies`, `src/memory.rs:3013-3016`), and `mem.signpost.doctrine.overview` is onboarding-tagged — so that memory body *is* a boot section today. Mechanism is applicable; content authority is not, which is exactly the ambiguity in (a).
- **SPEC-010 / PRD-003 (skills distribution)** — owns the skill *tree and delivery* (`plugins/` canonical, embedded at `src/install.rs:20`, dual-channel install), not skill *content* or format. Applicable only if the change re-homes or re-formats skills.
- **ADR-001 (module layering)** — binds the implementation (leaf ← engine ← command, enforced by `tests/architecture_layering.rs`) but decides nothing about the governance question; noted so it is not mistaken for a content constraint.
- **ADR-003, ADR-004, ADR-009, ADR-010, ADR-016, ADR-018** — the change loop, outbound-only relations, lifecycle/conduct, relation contract, intent-as-role, provenance axes. All are the substrate the change *rides* (via REV/REV-relations); none constrains corpus content, format, or publication target.
- **PRD-006 / SPEC-009 (install)** — projection mechanics, write-if-absent, root detection, embed. Applicable to *root reorganisation* under (b), but it does not govern what is published or how the corpus reads; the publication side is SPEC-026's.
- **STD-002 alone** — relevant only if the change renames entities/slugs; not independently binding otherwise.
- **RFC-017 (open)** — tier 5, asserts no canon, but is the nearest prior statement of the *learning* intent (tour/quickstart/mental model). It is evidence, not constraint; see Revision candidates.
- **RFC-033 itself** — tier 5 and governance-neutral (ADR-014 D1): it must not be cited as authority for the change it deliberates.

### Revision candidates

- **ADR-005** — needs amendment (or a superseding ADR) rather than a REV alone, because the gap is a *missing axis*, not a stale delta. The blocking clauses: §Decision invariant "There is exactly **one** workflow doc (`routing-process.md`) — no parallel summary" and §Invariants R-OQ-4 (the restate line). ADR-005 tiers knowledge by *access pattern* and deliberately names no source; a "single source of truth for the conceptual corpus" is a new (derivation) axis that ADR-005 neither grants nor forbids. Also stale: its §References to `src/skills.rs`. Per ADR-013/ADR-014 the resolution should route through a `REV` descending from ADR-005, and if the axis is added, ADR-005 itself is amended.
- **SPEC-026 + PRD-017** — require a Revision (or a new descending PRD/tech spec) to permit (c). Blocking clauses: SPEC-026 FR-001 "Publication manifest is the sole authority for the public set"; D3 "The library is read-only by construction… no mutating verb"; D6 licence closed set **{MIT, GPL}** fail-closed; PRD-017 §2 "Out of scope: Projecting or materializing anything into a client repo — the library only reads and emits." A publish-*out* web target is none of these. Either extend the publication model with an outbound/export seam, or fence the blog explicitly out of doctrine governance. The census's gap 4 ("External publication ungoverned") is independently confirmed: `grep -rli "personal blog\|public web\|external web\|web target"` over `.doctrine/spec .doctrine/adr .doctrine/policy .doctrine/standard` → **nothing** (positive control: the same corpus contains SPEC-026 for "web"/"publish" in other senses).
- **ADR-024** — a Revision is needed *only if* blog republished material must obey the grounding rule. Blocking clause: §"Scope fence. This governs **shipped** assets. It does not govern slice prose, design docs, specs, reviews, this repository's own governance, or its source and tests." A blog reader has the *same* silent-substitution failure ADR-024 exists to prevent (a repo-private `ADR-005` resolves to the reader's own unrelated record), but the scope fence excludes them. Decide: extend the rule to any public-facing surface, or record the fence as deliberate.
- **SPEC-011 / PRD-007** — a Revision if the change alters the boot section/source taxonomy (`boot_sequence`, `src/boot.rs:104-139`) — e.g. demoting the inlined onboarding memory body now that it duplicates a memory. The boot is a pure projection with a cache-key; a source change is spec-visible.
- **DEC-010** — must be settled or superseded. It is `proposed`, `governed_by ADR-019`, and asserts "Published set = full projection complement (Option A)"; SL-242 §Context already flags it as "out of date with SL-227." If the corpus is unified, the complement invariant (`src/publication.rs:1009-1014`) moves with it and DEC-010 is the record of that question.
- **SL-144 / CHR-023** — not governance, but blocking open work: SL-144 is `ready` 0/5 and its scope reconciliation is dated 2026-07-03, *predating* ADR-019 (SL-242 OQ-2 names this). It must be re-scoped or superseded before the change routes, or the change duplicates it.
- **RFC-017 → RFC-033** — RFC-017 (open) already scopes human onboarding (tour/quickstart/mental model), and RFC-033's title subsumes it. Per ADR-014 an RFC asserts no canon, so the resolution is: merge/supersede RFC-017 into RFC-033's deliberation, then land the outcomes as `REV`(s) descending from ADR-005 (+ ADR-019/ADR-024, + a new PRD if (c) is in scope). The census's boundary proposal — a PRD at product altitude plus a tech spec at container altitude — matches the RFC-021/ADR-019 precedent (root ADR → descending specs).
- **STD-002** — only if the unification renames titles/slugs; not otherwise.

### Open questions this thread cannot settle

1. **What "single source of truth" is meant** — *authoring* source (one file others mechanically derive) vs *governance owner* (one artefact owns the rule, others cite). ADR-005 chose access-pattern tiering precisely to avoid a single physical source; the change may be asking for the opposite. The two readings imply different revisions.
2. **Whether the personal blog is in doctrine's product scope.** `publication/manifest.toml` and SPEC-026 treat publication as a *client-repo* read seam; a blog is an external write target. Answering "in scope" implies a new publication contract (export seam, licence, citation grounding, format), answering "out of scope" implies a fence in PRD-017/SPEC-026. Both are large.
3. **The licence of the shipped memory corpus.** The engine is `GPL-3.0-only` (`Cargo.toml:6`) and `install/` is uniformly MIT, but the memory corpus is not in the publication manifest and carries no per-asset declaration (PRD-017 OQ-1 leaves memory-corpus publication-for-copy open). Republishing any of it publicly requires this settled.
4. **What "unify the authoring format" ranges over** — the surfaces listed are heterogeneous (entities in TOML+MD, skills as `SKILL.md`, `install/*.md` prose, `README.md`, a TypeScript frontend). Whether the change means one format or one *IA over* heterogeneous formats is unresolved, and SPEC-016/SPEC-005/SPEC-019/SPEC-031 each own a per-kind format contract that constrains the answer.
5. **Whether a public reading surface reuses the loopback explorer** (SPEC-025 is loopback-only, PRD-016 local-first) or needs a separate render path — not decidable from governance; it is a design decision downstream of the PRD.
6. **Enforcement home.** STD-003 binds "no silent skip," but no shipped check exists: SL-242 §Objective 4 proposes a doctor currency check that `src/doctor_checks.rs` does not yet implement. Whether the unified-source invariant is enforced by a doctor check, a boot assertion, or a new kind is open.
