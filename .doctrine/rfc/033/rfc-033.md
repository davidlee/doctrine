# RFC-033: Learning surface: corpus unification and format

<!-- Reference forms: doc/glossary.md § reference forms. -->

**Status: open.** This RFC asserts no canon (ADR-014). It states the goal,
measures the corpus, records the frame chosen in discussion, and lays out the
descent. The evidence behind every claim below is in `research/research.md`,
which cites `research/raw/` for bulk.

## Context

### The request

Doctrine is written for agents to *operate* and for its author to *maintain*.
The request is to make it learnable — by both audiences, without it ceasing to
be either. Three observations prompted this RFC:

1. The reading surface (`doctrine onboard`) is a one-shot entry into the graph
   explorer, focused on a single node. It works as a viewer; it is not built as
   a teaching surface.
2. The shipped memory corpus reads as accrual rather than curriculum — 21
   signposts, 8 concepts, 4 patterns, 2 facts, accumulated by different sessions
   with no reviewing pass to hold voice, altitude, or sequence together.
3. The published reference library overlaps the memory corpus conceptually, with
   no stated relationship between them.

Any downstream consumer of the corpus — a rendered website included — is served
by the right documents existing in one place. Such consumers are not a concern
of this RFC.

### The corpus, measured

| surface | extent | lines |
|---|---|---|
| boot snapshot (generated, resident every session) | 31 sections | 627 |
| shipped memory corpus | 35 memories | 1 260 (bodies) |
| published reference library | 17 docs, 15 published | 2 182 |
| skill masters | 39 skills | 5 315 |
| README | 1 | 343 |

### The overlap, evidenced

One conceptual corpus — the entity engine, storage model, storage tiers, reading
entities, the memory model, the boot snapshot, the routing gate, the core loop,
the TDD loop, the conventions, "the CLI is the source of truth" — is published
across those surfaces at least four times:

- The "CLI is the source of truth" rule appears in **24 files**.
- Storage tiers and the storage rule appear in **8**.
- The core loop appears in **7**, in **three different orderings**.
- The 82-line `mem.signpost.doctrine.overview` memory is inlined **verbatim**
  into the boot snapshot's `## Onboarding` section (SL-187: every
  `onboarding`-tagged memory is inlined), and therefore into every session's
  cached prefix. It restates the pillars, the storage tiers, the CLI rule, and
  the core loop.
- `mem.signpost.doctrine.reference-docs` indexes 4 documents; the publication
  register carries 18 entries.
- `install/routing-process.md` both feeds the boot snapshot and is itself a
  published reference document.

Nothing states which of these is the source and which are derived. ADR-005
(*Shipped knowledge is tiered by access pattern; skills route, reference docs
explain*) fixes the tiers and **deliberately nominates no source**. So this is
not a broken rule to repair; it is an axis the governance never had.

## Discussion

### Goals

- **G-1 — One normative home per rule.** A rule or concept about doctrine has
  exactly one owning artefact. Every other surface derives from it or cites it.
  Other documentation modes (tutorial, explanation) may paraphrase, but must
  cite the owner. This is ADR-005's "single source per fact", made precise
  enough to enforce.
- **G-2 — Two audiences, honestly served.** Agents need dense, pull-on-demand,
  cited orientation. Humans need a path with a beginning, an order, and a voice
  that assumes nothing. Today only the first exists.
- **G-3 — One authoring discipline.** Each kind of material has a declared home
  and a declared form, so a new fact has an obvious place to go.
- **G-4 — Drift is caught where it can be.** STD-003 forbids silent
  degradation. Derived material is checked by regeneration; citations are
  checked for resolution. Paraphrase that silently restates a rule is not
  mechanically detectable and is left to review — this RFC does not claim
  otherwise.
- **G-5 — Learnable in bounded attention.** RFC-017's reframe holds: doctrine's
  use is agent-mediated, so the human set is small and finite — why, the mental
  model, and a path to first success.

### Two senses of "single source"

- **Authoring source** — one artefact holds the text; others are *mechanically
  derived* from it (SPEC-018's `RELATION_RULES`; `boot_sequence` for the boot
  snapshot).
- **Governance owner** — one artefact *owns* the rule; others **cite** it and
  stay consistent by discipline and review.

Different material wants different treatment. The current corpus does neither
consistently: it copies.

### Options considered

- **O1 — Reference library owns the concepts;** memories and boot point at it.
- **O2 — One entity corpus, many renders.** Every shared concept becomes an
  entity and every surface a projection. The only option under which
  duplication is *impossible*, and by far the most expensive: it reaches into
  the entity engine and every per-kind render contract (SPEC-005, SPEC-016,
  SPEC-019, SPEC-031).
- **O3 — Two parallel corpora** (memories, reference docs) with one discipline
  and declared relationships both ways.
- **O4 — Status quo plus enforcement.** A first increment of O3, not a distinct
  destination.

The options conflated three independent questions — where the source lives,
which voice a document speaks in, and how drift is enforced. The frame below
answers each separately.

### The frame (chosen in discussion, 2026-09-26)

**One information architecture over the existing serialisations; ownership by
material type.** O2 is rejected as disproportionate: one architecture is enough
for G-1 and G-3, and the file formats stay as they are.

| material | home | other surfaces |
|---|---|---|
| structured / generated (vocabularies, command shapes, boot sections) | code or the publication register | derived; checked by regeneration |
| rules and concepts | the reference library (`install/*.md`, published as `reference/*`) | cite by `<name>.md` |
| agent orientation, gotchas, project-local facts | memories | memories point at the library for anything it owns; they do not restate it |
| routing | skills | unchanged (ADR-005) |
| human orientation (RFC-017's set) | its own documentation mode | may paraphrase; must cite the owner |

The boot snapshot carries pointers, not restatements: the inlined overview
memory is the first thing this frame removes.

### Enforcement

Reuse existing machinery; no new kind.

- `boot --check` covers the resident tier.
- The publication register's derived completeness invariant, plus the doctor
  check SL-242 proposes, covers citation resolution.
- Restatement is caught in review, and by SL-144's restate-line audit carried
  forward into the library slice.

### Licence

The engine is `GPL-3.0-only`; `install/` is MIT; the shipped memory corpus and
the skill corpus carry no declared licence. Under this frame the licence
question no longer blocks anything — the owning corpus is already MIT, and the
memory corpus becomes pointers — but it should still be settled.

The concern with MIT is that detailed MIT-licensed descriptions of a GPL
program's interfaces might weaken the program's licence. Copyright protects
expression, not interfaces or methods, and documentation grants no rights to
the code it describes. The same exposure, if any, already exists in `install/`
(`using-doctrine.md` documents the command surface in detail), so extending MIT
to memories and skills adds no new category of risk. A copyleft licence on
skills would, by contrast, burden every client repo they are installed into.
Leaning MIT; not legal advice, and worth a qualified opinion before it is
recorded as policy.

### Already rejected — do not re-propose

The web UI as the primary documentation; a comprehensive manual; a video tour;
the name `project-onboarding.md`; a second link store for memories; a bounded
published set; restoring projection for the reference tier; rewriting every
citation to carry `library show`; a client migration primitive; one signpost
per verb; hand-authored diagrams. Sources in `research/research.md`.

## Outcome

**Frame settled; descent open.** The user chose (2026-09-26): the reference
library as the normative owner of rules and concepts, memories as pointers
(OQ-1, OQ-2, OQ-3); downstream publication out of scope (former OQ-4, OQ-8);
SL-144 dropped (OQ-7).

### Descent

1. **Now — needs no further decision.**
   - Stop inlining the overview memory into boot: drop its `onboarding` tag
     (OQ-9), leaving the project orientation memory as the resident entry.
   - DEC-010 → accepted (SL-227 implemented it and is done).
   - SL-144 → abandoned; CHR-023 stays open for this programme to fulfil.
   - SL-242 proceeds.
2. **Governance.** One Revision on ADR-005: nominate the home for each material
   type (the frame table) and state the citation rule (G-1); amend ADR-024 so
   library citations carry a `lib:` marker (`lib:reference/glossary.md`).
   This is REV-067. Migrating existing bare `<name>.md` citations falls to
   S1 (library, boot, skills) and S2 (memories); S4 checks them. Amend SPEC-011
   (boot sources) and SPEC-026 (publication) in the same Revision if the
   descent needs it. No new PRD; no new tech spec — the frame needs no new
   mechanism.
3. **Slices.**
   - **S1 — Reference library architecture.** Consolidate each rule into its
     owner; carries forward SL-144's structure and restate-line audit;
     fulfils CHR-023.
   - **S2 — Memory corpus as curriculum.** Rewrite memories into pointers plus
     agent-only material, sequenced; absorbs SL-242's remainder.
   - **S3 — Human documentation set.** RFC-017's positioning, tour, quickstart,
     mental model, and FAQ, citing S1's owners. RFC-017's own open questions
     become S3's design inputs.
   - **S4 — Enforcement.** The citation-resolution check over memories, skills
     and the human set.
   - **S5 (later, optional) — Teaching path in `onboard`.**

### Open questions

- **OQ-5** — Licence of the shipped memory and skill corpora. Leaning MIT;
  non-blocking; wants a qualified opinion first.
- **OQ-10** — RFC-017: resolved as absorbed; it closes when S3 is scoped.
- **OQ-11** — G-5 needs a measure (a page or reading-time budget for the human
  set) before S3's design locks.
