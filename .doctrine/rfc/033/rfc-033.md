# RFC-033: Learning surface: corpus unification, format, and publication

<!-- Reference forms: doc/glossary.md § reference forms. -->

**Status: open.** This RFC asserts no canon (ADR-014). It states the goal,
measures the corpus, sets out the options, and stages the decision. The evidence
behind every claim below is in `research/research.md`, which cites
`research/raw/` for bulk.

## Context

### The request

Doctrine is written for agents to *operate* and for its author to *maintain*.
The request is to make it learnable — by both audiences, without it ceasing to
be either. Four observations prompted this RFC:

1. The reading surface (`doctrine onboard`) is a one-shot entry into the graph
   explorer, focused on a single node. It works as a viewer; it is not built as
   a teaching surface.
2. The shipped memory corpus reads as accrual rather than curriculum — 21
   signposts, 8 concepts, 4 patterns, 2 facts, accumulated by different sessions
   with no reviewing pass to hold voice, altitude, or sequence together.
3. The published reference library overlaps the memory corpus conceptually, with
   no stated relationship between them.
4. Publishing a web version of the reference material on a blog presupposes a
   single, sane format — which does not exist today.

### The corpus, measured

| surface | extent | lines |
|---|---|---|
| boot snapshot (generated, resident every session) | 31 sections | 627 |
| shipped memory corpus | 35 memories | 1 260 (bodies) |
| published reference library | 17 docs, 15 published | 2 182 |
| skill masters | 39 skills | 5 315 |
| README | 1 | 343 |

### The overlap, evidenced

One conceptual corpus — the entity engine, storage model, storage tiers, reading
entities, the memory model, the boot snapshot, the routing gate, the core loop,
the TDD loop, the conventions, "the CLI is the source of truth" — is published
across those surfaces at least four times:

- The "CLI is the source of truth" rule appears in **24 files**.
- Storage tiers and the storage rule appear in **8**.
- The core loop appears in **7**, in **three different orderings**.
- The 82-line `mem.signpost.doctrine.overview` memory is inlined **verbatim**
  into the boot snapshot's `## Onboarding` section, and therefore into every
  session's cached prefix. It restates the pillars, the storage tiers, the CLI
  rule, and the core loop.
- `mem.signpost.doctrine.reference-docs` indexes 4 documents; the publication
  register carries 18 entries.
- `install/routing-process.md` both feeds the boot snapshot and is itself a
  published reference document.

Nothing states which of these is the source and which are derived. ADR-005
(*Shipped knowledge is tiered by access pattern; skills route, reference docs
explain*) fixes the tiers and **deliberately nominates no source**. So this is
not a broken rule to repair; it is an axis the governance never had.

### Why an RFC

- The boundary is undecided: four governance artefacts bear on it (ADR-005 on
  tiering, ADR-019 on the asset vocabulary, ADR-024 on grounding, SPEC-026 on
  publication), and they intersect rather than nest.
- Two open slices already sit on this ground: SL-144 (`ready`, scoped before
  ADR-019) and SL-242 (`proposed`) both edit `install/manifest.toml`.
- The decision has a legal edge: the engine is `GPL-3.0-only`, `install/` is
  MIT, and the shipped memory corpus carries no per-asset licence at all.
- RFC-017 (*Human onboarding docs: tour, quickstart, mental model*) already
  proposes the human-facing document set, and is open and partly overtaken by
  events. Any resolution here must absorb it rather than compete with it.

### What this RFC does not do

It does not choose. It names the decision, separates the axes that are
currently tangled into one idea of "one sane format", and stages the order in
which they must be settled.

## Discussion

### Goals

- **G-1 — One source per fact.** A fact about doctrine has exactly one home,
  and every surface that shows it either derives from that home or points at it.
  This is ADR-005's own "single source per fact" made enforceable rather than
  aspirational.
- **G-2 — Two audiences, honestly served.** Agents need dense, pull-on-demand,
  cited orientation. Humans need a path with a beginning, an order, and a voice
  that assumes nothing. Today only the first exists.
- **G-3 — One authoring discipline.** Whatever a fact's home is, its form is
  declared and consistent, so that a new fact has an obvious place to go and an
  obvious way to look.
- **G-4 — Publishable without duplication.** The public web version is a render
  of the corpus, not a second copy of it.
- **G-5 — Drift is loud.** STD-003 forbids silent degradation. Whatever model
  lands must have a check that fails when a surface diverges from its source.
- **G-6 — Learnable in a bounded amount of attention.** RFC-017's reframe holds:
  doctrine's use is agent-mediated, so the human set is small and finite — why,
  the mental model, and a path to first success.

### Axis 1 — two senses of "single source"

The phrase hides two different arrangements, and conflating them is the main
source of confusion in the current corpus:

- **Authoring source** — one artefact holds the text; the others are
  *mechanically derived* from it. This is what SPEC-018 did for the relation
  vocabulary, whose source is `RELATION_RULES` in code, "pointed at, never
  transcribed", and what `boot_sequence` already does for the boot snapshot.
- **Governance owner** — one artefact *owns* the rule; the others **cite** it by
  name and are expected to stay consistent by discipline and review, not by
  generation.

Both are legitimate, and different material wants different treatment. A
generated table must be derived. A convention that a reader needs in context
usually wants to be cited, because a pointer is cheaper than a copy and survives
re-wording. The current corpus does neither consistently: it copies.

### Axis 2 — what "one format" ranges over

The surfaces are heterogeneous by construction: entities are TOML plus prose,
skills are `SKILL.md`, reference documents are standalone markdown, the README is
a landing page, and the reading surface is a TypeScript application. "One
format" can therefore mean:

- one *serialisation* for all prose (for example, everything becomes an entity),
  which is a large change to the entity engine and to per-kind render contracts
  (SPEC-005, SPEC-016, SPEC-019, SPEC-031); or
- one *information architecture* over several serialisations — a declared set of
  document types, a declared altitude for each, and declared relationships
  between them, with the bytes remaining as they are.

The second is much cheaper and is enough for G-1, G-3 and G-4. The first is the
only one that makes duplication *impossible* rather than *visible*.

Worth noting from outside: Diátaxis, the dominant published framework for this
problem, identifies four needs and four forms — tutorials, how-to guides,
technical reference, explanation. Doctrine's corpus is almost entirely reference
and explanation, with no tutorial and no human-voiced orientation. That is
RFC-017's diagnosis reached independently, and it suggests the gap is in *mode
coverage*, not only in organisation.

### Axis 3 — publication target

Today "published" has exactly one meaning (SPEC-026): an entry in the
publication register, readable through `doctrine library`, licence-declared, and
read-only by construction. Three publication *targets* are in play and only one
is governed:

| target | status |
|---|---|
| the boot snapshot (resident) | governed by SPEC-011 / PRD-007 |
| the published library (client-repo read path) | governed by SPEC-026 / PRD-017 |
| a public web version (blog) | **ungoverned** |

The blog is a publish-*out* target, and the governed model is a read-*in* one.
Admitting it means either extending the publication model with an outbound
export contract, or fencing the blog explicitly out of doctrine's scope. It
cannot be settled as a detail of the format work.

Two constraints bite before any publishing happens:

- **Licence.** The engine is `GPL-3.0-only`; `install/` is uniformly MIT; the
  shipped memory corpus has no declared licence and is absent from the
  publication register. SPEC-026's licence set is fail-closed. Nothing from the
  memory or skill corpora can be published publicly until this is settled.
- **Grounding.** ADR-024 requires every claim in a shipped asset to resolve for
  the reader. Its scope fence excludes this repository's own ADRs, RFCs and
  specs — so public material inherits no such rule, even though a reader hitting
  a bare `ADR-005` suffers exactly the failure ADR-024 exists to prevent.

### Options

**O1 — Reference library is canonical.** `install/*.md` (published as
`reference/*`) becomes the source; memories and the boot snapshot become derived
digests; the blog publishes the same set.
*Cost:* the memory corpus must be re-derived, and the resident tier loses the
ability to hold material the library does not.
*Preserves:* the published register as sole authority; the licence position
(already MIT).
*Breaks:* RFC-017's argument that agent-voiced reference "presumes the mental
model it should be teaching" — unless the library itself gains human-voiced
modes.

**O2 — One entity corpus, many renders.** The shared concepts become entities;
the boot sections, memories, reference documents and blog pages are all
projections of them, using ADR-019's existing vocabulary of embedding,
publication and projection.
*Cost:* the largest change. It touches the entity engine, the render contracts
of each kind, and the boot projector.
*Preserves:* ADR-019's vocabulary without new words; the existing projection
pattern; and it is the only option under which duplication is *impossible*
rather than merely visible.
*Risks:* a loose render contract could recreate RFC-017's "second competing
explanation tier" inside one entity.

**O3 — Two corpora, one format, declared relationships.** Memories (agent voice,
pull) and reference documents (human voice) remain distinct bodies but share one
authoring discipline and one architecture, with declared relationships both ways.
*Cost:* moderate; mostly editorial and architectural, plus an enforcement check.
*Preserves:* each audience's voice; ADR-005's tiering as a premise.
*Breaks:* nothing — but it makes duplication *visible*, not impossible, so G-1
depends entirely on G-5's check being real.

**O4 — Status quo plus enforcement.** Accept two or four surfaces; add the
currency check and a declared relationship between them; fix the concentrated
duplication (the overview memory, `routing-process.md`).
*Cost:* lowest, and it can start immediately.
*Preserves:* everything in flight, including SL-144 and SL-242.
*Breaks:* G-4 — a blog remains a second copy — and leaves G-1 aspirational.

**O5 — Fence the public target** (a modifier, not a whole option). Declare the
blog outside doctrine's governance: publish the repository's own material under
its own licence, with its own citation discipline, and let doctrine's publication
model stay a read-*in* path.
*Cost:* lowest of all; it deletes a whole limb of work.
*Breaks:* G-4's "publishable without duplication" — though only if the blog
renders from the repository rather than restating it, which is compatible.

### Already rejected — do not re-propose

The following were considered and rejected previously, with reasons recorded; an
RFC that re-proposes them wastes the reader's attention: the web UI as the
primary documentation; a comprehensive manual; a video tour; the name
`project-onboarding.md`; a second link store for memories; a bounded published
set; restoring projection for the reference tier; rewriting every citation to
carry `library show`; a client migration primitive; one signpost per verb;
hand-authored diagrams. Sources in `research/research.md`.

### Enforcement

G-5 has no home today. The candidates, in increasing weight:

- a **doctor check** (the shape SL-242 already proposes) that fails when a
  published asset or boot section diverges from its source;
- a **boot assertion**, alongside the existing `boot --check`, covering the
  resident tier specifically;
- a **new kind** — a corpus register entity — which is the most expressive and
  the most expensive, and which risks re-inventing the publication register.

Reuse of the existing publication register is preferred: it is already a sole
authority, licence-declared per entry, with a derived completeness invariant.

### The staged decision

The axes above must be settled in order, because later answers depend on earlier
ones:

1. **Frame (this RFC's `OQ-1`, `OQ-2`).** Which sense of "single source", and
   which option. Output: a recorded choice, or an ADR if the choice is
   project-global.
2. **Governance.** A Revision descending from ADR-005 — amending it, and
   ADR-019 and/or ADR-024 as decided — plus a new PRD at product altitude if the
   public target is admitted.
3. **Technique.** A tech spec at container altitude: the composition and
   derivation model, the render paths, the enforcement check.
4. **Work.** Slices: the format and architecture; the corpus rewrite; the
   reading-surface experience; the publication pipeline.

**Gate before stage 1.** SL-242's `OQ-2` (its sequencing against SL-144) and
SL-144's disposition must be settled first, or the programme duplicates or
collides with work already in flight. DEC-010 and QUE-172 should be settled or
superseded in the same pass; both are stale records about the published set.

### Absorbing RFC-017

RFC-017 is not a competing proposal; it is the human-facing half of this one. Its
five documents (positioning, tour, quickstart, mental model, FAQ) become the
human render target of whichever option lands, and its `OQ-1`…`OQ-7` become
inputs to this RFC's discussion. Two of its premises need refreshing: a
human-facing on-ramp now partly exists (`doctrine onboard`, clickable memory
wikilinks, a projected orientation document), and its proposed in-repo `docs/`
home is occupied by vendored material.

## Outcome

**Open.** This RFC concludes that the decision is staged, not singular, and that
it must clear an in-flight-work gate before it starts.

**Ordering agreed:** stage 1 (frame) → stage 2 (Revision, plus a PRD if the
public target is admitted) → stage 3 (tech spec) → stage 4 (slices). ADR-005 is
the pivot artefact; RFC-033 is governance-neutral and cannot be cited as
authority for its own outcome.

**Open questions.**

- **OQ-1** — Which sense of "single source" is meant overall — authoring source,
  governance owner, or a deliberate mix by material type?
- **OQ-2** — Which option (O1–O4), and is O5 (fence the public target) accepted
  as a modifier?
- **OQ-3** — Does "one format" mean one serialisation, or one architecture over
  several? If the former, how far into the entity engine and the per-kind render
  contracts does it reach?
- **OQ-4** — Is a public web target in doctrine's product scope? If yes, what is
  its contract — export path, citation grounding, refresh cadence? If no, where
  is the fence written?
- **OQ-5** — What is the licence of the shipped memory corpus, and of the skill
  corpus? (Blocking for anything public.)
- **OQ-6** — Where does enforcement live — doctor check, boot assertion, or a new
  register — and at what cadence?
- **OQ-7** — What is the disposition of SL-144 (re-scope, re-sequence behind
  SL-242, or supersede), and of the stale records DEC-010, QUE-172 and IMP-232?
- **OQ-8** — Does ADR-024's grounding rule extend to public-facing material, or
  is its scope fence deliberate and recorded?
- **OQ-9** — Which boot sources survive? Specifically, does the inlined
  onboarding memory body remain, now that it is the densest duplication node and
  rides every session's cached prefix?
- **OQ-10** — How does RFC-017 resolve — merged into this RFC, superseded by its
  outcome, or left standing for its own descent?

**What resolving this must produce:** a Revision descending from ADR-005; a PRD
if OQ-4 admits a public target; a tech spec at container altitude; and a
disposition for SL-144, SL-242, DEC-010, QUE-172 and IMP-232.
