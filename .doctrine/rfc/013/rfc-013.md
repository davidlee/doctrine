# RFC-013: Prompt cascade selection algebra: composable trait categories and disjunction-via-classification

## Context

The prompt cascade (SL-186 resolver engine + SL-187 delivery) composes
per-context instruction from `install/hymns/**` (Framework) ⊕ `.doctrine/hymns/**`
(User) by matching each snippet's **selector** against a **context vector** and
concatenating the survivors. SL-186's design intent for the `model` band was a
**user-definable, composable, category-based** space of axes — but its `design.md`
compaction flattened that to a single `<vendor>/<name>` path, and the delivered
engine (`src/hymns.rs`) encodes exactly the flattened version: `ContextVector.model:
Option<String>` — one key per context.

SL-191 (the dispatch **worker contract** slice) is the forcing function that
surfaced the loss. Authoring worker guidance revealed that "deepseek guidance" is
not about a model id at all — it is guidance for an agent that is *pretty smart*
but has *questionable adherence*, performing the *worker role*. Those are
**orthogonal trait axes**, and the intended authoring keys hymns on them:

```
model/adherence/low
model/capability/code/high
model/capability/reasoning/high
```

not `model/deepseek/deepseek-v4-pro`. Model identity is a **leaky proxy** for a
trait-tuple: it does not reuse to the next loose model, it fuses identity with
trait, and it mis-fires the day a model's real traits diverge from its vendor path.

This RFC is the durable home for that nuance and for the **selection algebra** it
implies — the design considerations that must not be compacted away a second time.
It is a **leading position**, not canon (ADR-014): the axioms below graduate
downstream into the **cascade technical spec**, and, where a mechanism decision is
adversarially locked, into an ADR and a Revision/slice. It asserts no governance today.

## Discussion

### 1. What actually varies — traits, not identity

Three orthogonal axes decide what an agent must be told:

- **capability** (smart ↔ dumb) — how much reasoning you can lean on;
- **adherence** (tight ↔ loose) — how far it colours outside the lines;
- **role** (worker vs orchestrator) — the job and its subset of boot context.

A deepseek worker wants `{smart × loose × worker}`. A strongly-aligned strong model
(claude) as a worker wants the role contract *without* the loose-agent crutches —
telling a smart, tight agent "don't shake hands with a chainsaw" is noise. The
guidance is not keyed to a **model**; it is keyed to a **position in trait-space**.
"Loose adherence" is the real category; deepseek is merely one occupant of it.

This is precisely why the cascade was designed for **user-definable, composable
selectors** rather than a filesystem winner-takes-one lookup. The `model/**` tree
was meant to be a sparse, user-authored **classification vocabulary**, not a model
registry (SL-186 P4/P5/P6). The trait framing is the honest reading of that intent.

### 2. The selection algebra (verified against `src/hymns.rs`)

**Matching is conjunctive across axes — always.** `matches(sel, ctx)`
(hymns.rs:319–346) is a chain of `if pinned && mismatch → return false`, returning
`true` only when *every* pinned axis matches. There is no OR branch across axes.

**A selector may pin any axis regardless of its band.** A snippet's **band** (its
slot's first path segment) decides *where in the output* it lands; the **selector**
carries all five axes (`harness, model, role, arm, stage`) independently
(hymns.rs:143–155). So a `role/worker.md` snippet with a sidecar `model=adherence/low`
resolves the selector `{role=worker ∧ model=adherence/low}` — matching loose workers
only. `role ∧ model` is a single expressible conjunction; the band never enters the
match logic.

**A prefix is a contiguous-subtree OR.** `model_matches(pat, ctx)` (hymns.rs:290)
succeeds when `pat`'s segments are a left-to-right prefix of `ctx`'s (with `_default`
as a per-level wildcard). So a snippet keyed at a shallow prefix `model=anthropic`
matches *every* deeper agent key `anthropic/opus/5.6`, `anthropic/haiku/*`, … — a
disjunction over its whole descendant subtree, for free. Bounds: **contiguous
subtree only** (cannot express `opus ∨ haiku` while excluding `sonnet`), **no
cross-root** (`anthropic ∨ openai` needs two snippets), direction shallow-selector →
deep-context.

**Consequence — hierarchy is a pre-baked OR, with exactly one decomposition per
axis.** A tree bakes *one* way to group its leaves ("everything under P"). Two
*orthogonal* groupings on the same conceptual surface (vendor-wise ∧ capability-wise)
cannot both be subtrees of one tree — which is exactly why the trait groupings want
to be **separate axes**, each its own tree. Probe result vindicates the multi-axis
design over a single `model/vendor/name` path.

**The geometric model.** Combining the above, one selector expresses:

> **(subtree-OR on axis₁) ∧ (subtree-OR on axis₂) ∧ … = an axis-aligned box** in
> the taxonomy product-space.

- within an axis: OR, but only a contiguous subtree (prefix);
- across axes: pure AND;
- across snippets: **union of boxes** (`resolve` filters then concatenates,
  hymns.rs:359–364) → any region, tiled.

What one selector *cannot* do: non-sibling OR within an axis (split into ≥2 boxes),
or any cross-axis OR (≥2 boxes). The cost of a target region is **box-count**
(snippet count) plus **shared-body duplication** across boxes; a well-shaped taxonomy
keeps box-count low because prefix-OR covers whole subtrees in one box.

### 3. The delivered gap — single-key context defeats composition

The engine is single-valued on the model axis: `ContextVector.model: Option<String>`
(hymns.rs:202). An agent is one **point** in the product-space, so it can carry
`adherence/low` **xor** `capability/code/high` — **not both**. The intended
orthogonal-category composition (`adherence/low ∧ capability/code/high ∧
capability/reasoning/high` all firing) is therefore **authored-but-undeliverable**
on the current engine.

**Minimal fix — agent as a set of points.** Make the *context* set-valued on the
model axis (`ContextVector.model: BTreeSet<String>`), and let `model_matches(pat,
ctx_set)` succeed when `pat` matches **any** member (membership). Then each declared
trait key is one point; a box matches if any of the agent's points lands in it; the
existing union does the AND-of-traits composition. Change surface: context type,
`model_matches`, `--model` CLI arity (→ repeatable), new composition goldens.

**Crucially, specificity/precedence are untouched.** `specificity()` reads the
*selector* (still one pattern per snippet — hymns.rs:306–314), never the context. The
D3 band-primary-axis machinery and all its goldens stand. No new **band** is needed
either — trait categories are labels *within* the `model` band (`adherence/*`,
`capability/code/*`, `capability/reasoning/*`), so INV-1's closed band registry is not
touched. (Whether "model" stays the band name for a trait space, or the band is
renamed/re-homed, is an authoring-clarity question for the spec, not an algebra one.)

### 4. The design axiom — disjunction lives in classification, not selector grammar

The tempting question is "should selectors gain an OR grammar?" The position here is
**no**, but as a *generative constraint*, not a slogan:

> **Disjunction belongs in the classification layer (tree shape / set membership),
> never in the selector's boolean grammar.**

**Grounding (the load-bearing reason).** Specificity is a **total order** only over
conjunctions. `specificity = (primary-axis depth, Σ other-axis depths)`
(hymns.rs:306) is well-defined because a conjunction has a per-axis depth. Ask "what
is the specificity of `harness=claude ∨ model=deepseek`?" and depth is *ill-posed*.
That total order is what `replaces` (INV-3), seal (INV-6), and last-word ordering
(INV-2) all rest on. **OR-selectors would not merely complicate the parser — they
would dissolve the ordering algebra the whole cascade depends on.** So disjunction is
*exiled to classification because that is the layer where it does not corrupt
ordering*: a set-valued context matched by membership keeps every selector
conjunctive (one pattern each → specificity intact) while the disjunction lives
harmlessly in the data.

This makes the axiom **generative**: when a new OR-need appears, it tells you what to
do — *give that axis a declarable, set-valued classification and shape its tree so the
disjuncts you want share a parent* — rather than reach for grammar.

### 5. Stress tests — where the axiom holds and where it frays

DNF fact: conjunctive selectors + union = **DNF at snippet granularity**; any boolean
target region is reachable by writing multiple boxes. The only costs are shared-body
duplication and double-emit to intersections (bounded, non-corrupting for prose).

- **T1 — loose ∨ dumb → guardrails.** Refactors cleanly to a derived trait
  `guardrail/high` declared on both defs; body lives once. Holds — the disjunction is
  over one axis with a mutable, per-entity declarable set (def frontmatter). **This is
  the in-domain case, and it holds.**
- **T2 — negation over an open axis** ("all workers *except* deepseek"). No negation
  in a conjunction. Refactor = positive trait on everyone-who-should; cost is a *new*
  def that forgets the trait **silently** misses the guidance. Explicit-by-default is
  arguably good but the failure is silent. **Watch-item.**
- **T3 — OR over a code-enum axis** ("`harness=claude ∨ harness=codex`"). The escape
  hatch needs a declarable set to hang a derived trait on, but `harness` is a bare
  enum with equality matching, owned by code — nowhere to stamp `harness-family/hosted`
  without a code change. **The derived-trait escape fails for non-classifiable axes.**
- **T4 — OR correlating axes of different owners/lifetimes** ("`harness=claude`
  (framework enum, install-time) ∨ user-overlay-tagged experimental (runtime)"). **No
  single entity can precompute a derived trait** spanning independently-matched inputs.
  Here you genuinely want selector-OR, or you duplicate. **Sharpest fray; niche.**

**The valve.** For T4 (and any residue), DNF-by-duplication is the pressure valve:
bounded cost, non-corrupting for prose. So the constraint never fully jams — it
degrades to duplication in exactly the cases classification can't reach.

**Verdict.** Conjunctive-only is a **nice simplifying constraint for this domain**
(trait guidance, where we own classification), with two named watch-items (T2
open-axis negation, T3/T4 OR over non-classifiable / cross-owner axes). Revisit
grammar-OR only if a real T4 case with intolerable duplication appears — and even
then, first ask whether the fix is making the offending axis classifiable, not
enriching the grammar. Adding boolean grammar buys the cross-owner case at the price
of DNF-in-every-author's-head **and** an ill-posed specificity that poisons
replaces/seal/last-word.

### 6. Where trait classification comes from (no registry)

For a trait selector to match, the context vector must carry the agent's trait set.
Source options and their standing:

- **Self-identification is unreliable for the axis that matters.** An agent can
  reasonably self-report capability, but a *loose* agent is exactly the one that will
  mis-declare its own adherence. Adherence must be **assigned**, not self-asserted.
- **Per-def declared trait set (recommended).** The worker **def** declares its trait
  categories in frontmatter — the deepseek-class def carries `{adherence/low,
  capability/code/high, capability/reasoning/high}`; the claude def carries
  `{adherence/high, capability/*/high}`. This is the honest form of SL-191's D1
  ("arm-asymmetric *by data*"): the coupling lives in the def's declared traits, never
  in an arm→model rule. The spawner (orchestrator) may override/augment at spawn where
  it knows more.
- **No central model→traits registry.** Each def self-declares; there is no
  `models.toml`. This keeps P4/P6 fully intact — a per-def trait set is small, slow
  (model-generation cadence, not weekly), and owned locally, which is a *different
  artifact* than the churny model-id→spawn-param list the design fenced. Splitting
  "identity we must not registry" from "classification we legitimately declare" is the
  conceptual repair, and it does not reopen R1.

### 7. User-facing / authoring considerations

The considerations an author (and the spec) must hold:

- **Author keys hymns on trait categories, not model ids** — `model/adherence/low.md`,
  `model/capability/code/high.md`. The negative *worker contract* (touch-only-declared-set,
  hermetic goldens, component-anchored paths, only-git-verb-is-commit) is **role band**
  (every worker); the loose-agent crutches (concrete>abstract, explicit negatives,
  high-density) are an **adherence/guardrail** category (loose occupants only).
- **Taxonomy shape is a design-time commitment.** One tree per axis = one OR
  decomposition; you cannot cheaply re-parent later. Shape each axis so the disjunctions
  you will actually want are subtrees (`adherence/needs-help/{low,med}` vs
  `adherence/fine/high` buys "low∨med−high" in one prefix box).
- **Cost model authors should reason in**: a target region costs *box-count* (snippets)
  + *shared-body duplication*. Prefer a well-shaped subtree (one box) over enumerating
  siblings (many boxes); reach for a *derived coarser trait* before duplicating a body
  across boxes.
- **A def declares its own trait set**; changing a worker's guidance profile is editing
  that set, not editing hymns. Hymns are the vocabulary; the def is the classification.

## Outcome

**Open.** Leading positions this RFC takes, each to harden downstream (cascade tech
spec / ADR / Revision-or-slice) as adversarial design locks it:

1. The `model` band is a **composable, user-definable classification space** of
   orthogonal trait axes, not a `vendor/name` identity path. Model identity is a leaky
   proxy for a trait-tuple.
2. The selection algebra is **selector = axis-aligned box (AND of contiguous-subtree
   ORs); corpus = union of boxes**; cross-axis is always AND; a selector may pin any
   axis regardless of its band.
3. **Disjunction lives in the classification layer** (tree shape / set membership),
   never in selector grammar — because specificity is a total order **only** over
   conjunctions, and that order is load-bearing for replaces/seal/last-word.
4. Delivering orthogonal-category composition is a **bounded engine change**:
   set-valued context on the model axis + membership matching + repeatable `--model`;
   **specificity, precedence, and the band registry are untouched**. This is framed as
   SL-186 **under-delivering its own composable-category design**, not new scope.
5. **Trait classification is per-def declared, not a central registry**; adherence is
   assigned (spawner/def), not self-identified; P4/P6 intact.
6. Conjunctive-only is a generative constraint with named fray-edges (T2 open-axis
   negation; T3/T4 OR over non-classifiable / cross-owner axes) and a non-corrupting
   duplication valve; grammar-OR stays out until a real T4 forces it.

**Forcing-function fork (SL-191).** SL-191 needs the composition capability to author
its trait-keyed hymns. Three ways to sequence the engine change: **(i)** fold into
SL-191 (scope widens); **(ii)** a precursor slice SL-191 `after:`s; **(iii)** a
**conformance Revision against SL-186** (delivered ≠ designed intent) — arguably the
truest provenance. Decision deferred to the SL-191 design loop / a `/consult`.

**Graduation path.** This RFC → the **cascade technical spec** (the durable "how" of
the resolver: the box/union algebra, the classification-not-grammar axiom, the
trait-vocabulary vs def-classification split). A mechanism decision worth ADR
altitude: *disjunction-via-classification* as a locked selection-algebra invariant.
The set-valued-context engine change lands via (iii) or (ii) above.
