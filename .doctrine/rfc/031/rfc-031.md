# RFC-031: Design run fitness

## Context

<!-- The forces at play: the problem, the question, and why it merits structured
     discussion. An RFC asserts NO canon — it is governance-neutral deliberation. -->

The managed design run (`doctrine design start|apply|resume|materialise`; engine
specified by `SPEC-029`, built by `SL-233`) is not yet fit for daily use. Since it
shipped it has cost more attention than it has saved. This RFC is the **program
home** for making it work well: what is wrong, in what order to fix it, and how
we will know it is fixed.

It is deliberately *not* `RFC-026` (*Design review response effectiveness*),
which studies the review/response process and uses the design run as its
instrument, and *not* `RFC-030` (*Inquiry map as a general interview substrate*),
which deliberates one component's purpose. Both feed this program; neither is it.

**Supersedes a prior assessment.** On 2026-08-15 the cluster was judged to need no
RFC — "~22 of 27 items are conformance work and want slices". The slices came
(`SL-251`, `SL-256`) but the cluster kept growing (~27 → ~38 open) and the runs
kept stalling. What is missing is not deliberation per item but a single place
holding **order, rationale and a fitness bar**.

### State on 2026-09-11

Runs in this repo's corpus:

| slice | run | note |
|---|---|---|
| `SL-244` | unreadable | a retired `ChangeEvent` variant fails the whole snapshot (`ISS-315`) |
| `SL-243` | drafting, rev 28 | parked |
| `SL-246` | inquiring, rev 19 | parked |
| `SL-258` | exploring, rev 5 | 12/14 nodes open, stalled since 2026-08-17 |
| `SL-251`, `SL-256` | locked | completed — both *about* the engine itself |

The only runs that reached `locked` since the engine shipped were slices repairing
the engine.

### Why it has gone badly

Read across the friction observations and `RFC-026` **E8** (the one measurement
of the shipped engine):

1. **The exit signal lies.** `apply` reports success for input it ignored
   (unknown keys, inert acts, wrong-stage acts) and — reportedly — failure for
   state that moved. An agent cannot drive a state machine whose transitions it
   cannot observe. Every other problem is amplified by this one.
2. **The contract is discovered by reading source.** E8.7: 0.63 source reads per
   engine call, 15 of 33 for payload shape; one agent read `tests.rs` to learn how
   to clear a gate. `SL-251` made payload contracts fetchable; gate conditions,
   next obligation and node text are still not surfaced (`IMP-390`, `ISS-298`).
3. **Editing prose is disproportionately expensive.** Section bodies move whole
   (~90 KB payload to change a paragraph, `IMP-430`); re-adopting a hand-edited
   `design.md` needs full section fingerprints that no verb emits (`ISS-320`,
   `ISS-348`) — the single most-reported friction.
4. **Machinery shipped ahead of use.** The inquiry map's edge kinds shipped with
   full render support; E8.3 measured nine nodes and zero edges over seventeen
   revisions. Nothing puts the map in front of the user (`ISS-299`).
5. **Stored state outlives the binary** (`mem.fact.design-run.snapshot-outlives-the-binary`)
   and the engine was not written as though it did — so every strictness fix
   trades against reading live runs (`QUE-219`).

## Discussion

<!-- The position(s) explored, pros/cons, alternatives considered. Free-form — this
     is a discussion artifact, not a decision record. -->

### Principle: use-driven, measured per step

Each track below lands as a slice, and each slice's close is followed by use on a
real (non-engine) design run before the next track's priority is re-judged. The
failure mode to avoid is the one that produced point 4: building from the backlog
rather than from observed use.

### Fitness bar — what "working well" means

Measured on a real slice's design run, start to `locked`, after a track lands:

| measure | baseline | target |
|---|---|---|
| source reads of `src/design_run/**` / prompt assets per engine call | 0.63 (E8.7) | ~0 |
| submissions that succeed but change nothing, or fail but change something | observed, uncounted | 0 by construction |
| payload bytes to change one paragraph of one section | ~90 KB | proportional to the delta |
| refused submissions per run spent on contract discovery | several per session | rare; each refusal names the fix |
| existing runs readable by the current binary | 5 of 6 | all |

The bar is the RFC's exit: when a run meets it, this RFC resolves and the
remaining cluster is ordinary backlog.

### Tracks, in priority order

Membership is judgement and lives here; **status is never recorded here** — query
it (`doctrine backlog list -t cluster:design-run`, `doctrine inspect RFC-031`).

**T1 — Truthful apply.** `SL-259`. Error ⇒ nothing landed; success ⇒ rows that
tell the truth; unknown or inert input ⇒ typed refusal; old snapshots readable.
Settles `QUE-219` as its first decision. Items: `ISS-315`, `ISS-333`, `ISS-328`,
`ISS-327`, `ISS-290`, `ISS-362`, `ISS-367`, `ISS-361`. *First because* every other
track's measurement depends on an honest exit signal.

**T2 — Section edit loop.** `ISS-320` (dup `ISS-348`), `IMP-430`, `ISS-356`,
`ISS-320`'s question *is the section map adding information at all?* *Second
because* it is the most-reported friction and the dominant token cost per revision.

**T3 — Contract legibility, residue.** `IMP-390` (the three candidates `SL-251`
left: next obligation, gate conditions, what is accepted), `ISS-298`, `ISS-360`,
`ISS-282`, node-question text on a CLI surface, `CHR-067`.

**T4 — Map surfaced, then judged.** `ISS-299` → `CHR-065` (re-measure) →
settle `QUE-218`. Only then the semantic tier (`IMP-386`..`IMP-389`) or its
retirement. `ISS-300`, `ISS-303` are ungated correctness fixes here. Coordinate
with `RFC-030`, whose thesis may reshape the map before T4 builds on it.

**T5 — Review integration.** `IMP-392` (findings onto the `RV` ledger; `DEC-125`),
`ISS-357`, `ISS-359`, `ISS-310`. The `SL-256` run's empty self-minted `RV` is the
motivating sighting.

**T6 — Durability and engine quality.** `IMP-412`, `IMP-366`, and test seams
`IMP-364` (dup `IMP-357`), `IMP-368`, `IMP-399`, `IMP-373`. Opportunistic —
ride other tracks' slices where they touch the same code.

### Open: repair or reduce?

Every track above repairs. The alternative is to cut: retire engine surface that
no run has used (map edge kinds, parts of the runbook set mode, the attestation
roster) so there is less to make truthful and legible. T4 already carries this
question for the map. Whether it applies more broadly should be answered after
T1 and T2, when a run can be measured honestly.
