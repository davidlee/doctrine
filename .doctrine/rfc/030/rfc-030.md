# RFC-030: Inquiry map as a general interview substrate

## Context

<!-- The forces at play: the problem, the question, and why it merits structured
     discussion. An RFC asserts NO canon — it is governance-neutral deliberation. -->

The inquiry map shipped in `SL-233` as one component of the managed design run.
Its originating idea was a **lightweight, mutable graph modelling the transient
state of a design interview** — at any altitude, from high-level ideation to
stepwise diagnosis, and expected to run to hundreds of small choices.

In the same lifecycle the design run also (a) mints durable knowledge records and
(b) enforces an agent-vs-human authority model. This RFC's thesis is that these are
three different jobs on three different timescales, and that fusing them is what
makes the map unfit for the first one.

**Terminology.** "Record" here means the seven knowledge kinds — `DEC`, `QUE`,
`ASM`, `CON`, `EVD`, `HYP`, `CPT` — *not* `doctrine rec` (reconciliation records).
The word is pinned because the ambiguity is live in this repo.

### The observed friction

Read from a cold `design resume` of `SL-258` (14 nodes, 12 open), the run holds
stage, cursor, the graph, and the blocking-set declaration — and **not one of the
positions taken**. Concretely:

1. **No slot for a held position.** `InquiryNode` carries
   `{id, question, provenance, lifecycle, disposition, parent, needs, seq}`. There is
   no field for reasoning. A node is `open` (nothing recorded) or `resolved`, and
   `InquiryNode::transition` *refuses* `Resolved` — the only route is
   `resolve(disposition)`, which requires a full `DEC-062` disposition.
2. **`body` is refused at `inq-`.** `Declaration::WIRE_KEYS` homes `body` at
   `IdKind::Section`; `inert_key` turns it into a refusal (`ISS-318`). Reasoning
   cannot be parked against a node even opportunistically.
3. **The cheap forms are coupled to resolution.** `unresolved { note }` and
   `non-durable { note }` do store a note in the run and mint nothing — but both set
   lifecycle `Resolved`, so using either to park a live position falsely settles the
   node and drops it off the frontier. The mechanism for a cheap provisional note
   exists and is wearing the wrong label.
4. **Reversal was never designed.** Minting runs the `DEC-086` six-step protocol with
   id reservation and a recovery journal. Un-minting is nothing: `transition` clears
   `disposition` (`ISS-303`), and no code path withdraws or supersedes the record the
   node pointed at — so reopening orphans a live `proposed` record in the corpus with
   nothing referencing it. That orphan half appears uncaptured.
5. **The provisional↔binding gradient exists but is invisible.** `DECISION_STATUSES`
   seeds at `proposed`; `ASSUMPTION_STATUSES` at `held`; `CONSTRAINT_STATUSES` at
   `active`. So "best of three for now" and "ironclad invariant" *are* expressible in
   the corpus. But the node stores `Disposition::Created { record }` — a bare id — so
   the run renders `inq-4 → DEC-112` and cannot say which it is.

The compound effect is an **inverted incentive gradient**: building graph structure
is cheap and needs no ratification, while recording substance requires a durable
governance act. An agent under context pressure does the cheap thing. `SL-258` shows
the predicted result — a rich 14-node graph with `resolved=0` and `sections=0`.

## Discussion

<!-- The position(s) explored, pros/cons, alternatives considered. Free-form — this
     is a discussion artifact, not a decision record. -->

### T1 — The separation is half-built already

`.gitignore:41` covers `.doctrine/state/design/`, so the map is **already
runtime-tier**: disposable, `rm -rf`-able, never committed (`DEC-059`). The
storage separation this RFC would propose largely exists.

What does not exist is a **cheap exit**. The only route out of the graph is the
`DEC-086` minting protocol. So the defect is not the tiering — it is the
**promotion seam**, which has exactly one gear and that gear is durable governance.
This is a smaller and better-located problem than "separate the two tiers".

### T2 — Proposal: the map is a substrate, the design run is one consumer

Strip minting out of the inquiry map, leaving a general interview graph with no
governance semantics; add a **design-run-specific promoter** that receives an
inquiry graph and mints selected records. The map then has standalone utility
outside the design run, which is the open question `QUE-206` already asks.

Consequences to weigh:

- If the map carries no governance semantics, it needs **no authority model at all** —
  nothing durable is at stake, so provisional movement is free and reversal is free.
- Authority concentrates at the promotion boundary, which happens a handful of times
  per slice rather than hundreds. That is the first point in the design where a
  genuinely unspellable human channel is *affordable*.
- Counter-consideration: concentrating authority at one gate also concentrates the
  risk. It makes the promotion-candidate mechanism load-bearing rather than a
  nicety.

### T3 — What selects the promotion set

`"the critical semantic framework for a slice"` is the load-bearing undefined term.
Three candidate selectors:

- **agent nominates** — reproduces the honesty problem one level up;
- **human ratifies** — real, but needs the channel T4 defers;
- **derived from structure** — `InquiryMap::needs_in_degree` already computes "how
  many other questions depended on this one", `needs` edges are deliberately
  sparse-minimal (`DEC-061`), and the frontier already trusts this as its second rank
  key. High in-degree is the framework; leaf-heavy tree is interview chatter.

The third is the `DischargeClaim` principle applied correctly: derive significance
from structure the agent had to build anyway rather than accept it on the agent's
word. It also reduces the human act to ratifying a short derived list.

**Open risk:** if exploration is transient, promoting a conclusion loses its
derivation. Promotion may need to carry the node's feeding subtree as the record's
rationale, or the trade is ceremony for amnesia. The existing seam is `/harvest` and
the slice notes' Harvest section — "gitignored but harvested at close" rather than
"gitignored and discarded".

### T4 — The authority model, and why this RFC defers it

Deliberately parked. Recording the finding so it is not rediscovered:

`AcceptanceAttestation` has real teeth against *content* laundering — its digest is
derived by Doctrine and bound, covering the checkpoint payload fingerprint, the
inquiry disposition, and the run revision, so an acceptance cannot be lifted onto
different content, a later revision, or a different disposition. What no digest over
content can bind is **presence**: whether a human was there at all. The agent
authors `basis`, `provenance: user-directed`, and `authority: user-pinned`.

The correct pattern is already in the codebase. `DischargeClaim` omits `verified`
from the wire because "a verifier result is exactly the kind of fact Doctrine must
derive rather than accept on a caller's word … there is no wire slot to claim one
through, so the category error is unspellable rather than refused." The same
principle is applied to verification and not to human presence.

**Why deferred:** what the gate *is* matters much less right now than basic fitness
for purpose. A single gate can afford a heavier authentication toll than every
transition in a conversation — that much is settled in principle. Designing it is
not on the critical path.

### T5 — QUE-218 and the fresh measurement

`QUE-218` (*Does the inquiry map earn a semantic tier?*) gates `IMP-386`, `IMP-387`,
`IMP-388`, `IMP-389` through inbound `needs`, so settling it unblocks four items at
once. It rests on `RFC-026` `E8.3` — 9 nodes, 0 edges of either kind, 17 revisions —
whose own update block already conceded that `ISS-360` prevents the instrument from
separating *did not use* from *could not use by the obvious route*.

`EVD-026` is the re-measurement `CHR-065` was waiting for, arriving unsolicited:
`SL-258` holds 14 nodes, 10 `parent` edges and 25 `needs` edges over 13 of 14 nodes,
multi-target and non-root, in 5 revisions — built with `ISS-360` still open, so the
per-level cost was paid deliberately.

**But the same run relocates the problem.** The frontier is *empty* with
`open_outside_frontier=12` and `blocked=13`, because `is_blocked` excludes blocked
nodes from frontier eligibility and at realistic density almost nothing is eligible.
The semantic tier is not unused — it is **unconsumed**. That promotes `IMP-389` and
`IMP-390` above the map-deepening batch, and it is a fitness argument rather than a
machinery argument, which is what `QUE-218`'s `why_matters` asks for.

## Outcome

<!-- If resolved: what was concluded (the body holds the yes/no — `status` stays
     outcome-blind). If open: what remains unanswered. -->

Open. Three questions this RFC exists to settle:

- **`QUE-218`** — does the map earn a semantic tier? `EVD-026` is new evidence; the
  reframe in T5 (used but unconsumed) is the proposed reading.
- **`QUE-206`** — is the interview substrate separable from slice design? T2 is the
  proposed answer.
- **Storage tier** — `DEC-059` (*Inquiry map uses a revisioned runtime TOML
  snapshot*) is **accepted**, so revisiting transience is a governance change and
  routes through a Revision per `ADR-013`, not a direct edit.

Not settled here, and deliberately: the shape of the promotion gate (T4).
