# RFC-015: Governance state on a dedicated ref namespace

<!-- Reference forms: entity ids padded (SPEC-022, ADR-012); doc-local refs bare
     (OQ-1). Origin: strategic review of the multi-harness dispatch design
     (RFC-014 walkthrough, 2026-07-05). -->

## Context

`.doctrine/` authored state and code share one repo, one git history, and one
set of branches — but they have different write disciplines and different
lineage needs. That single seam generates a recurring family of witnessed
failures, each patched locally:

- **R-5 belt** — workers must be forbidden from touching `.doctrine/` /
  `.claude/` in their deltas (SPEC-012 REQ-249), because governance state is
  physically present in every code worktree.
- **Knowledge-trails-code** — memory/AC-evidence/notes must be ordered after
  the confirmed code commit (ADR-006 D7), and the four-bucket temporal
  classifier (ADR-012 D2) exists to project slice-orthogonal knowledge ahead
  of held-back code.
- **Split-brain authored state** — status flips and reconciliation writes made
  on the coordination tree diverge from the primary tree's view (IMP-174);
  split-lineage dispatched slices become un-closeable (IMP-236, IMP-201);
  instrumentation appends target the wrong tree (IMP-258).
- **Memory orphaning** — memory committed inside a worker fork is severed by
  squash/sever; the content survives but the git anchor lies (worktree skill;
  SPEC-012 NF-002 context). Hence the standing gotcha "record durable memory
  on trunk, never inside a fork."
- **Evidence-ref stripping** — `phase/<N>-NN` code cuts must filter
  `.doctrine/` out (ADR-012 D3), because code history is born impure.

These are five patches on one structural tension. This RFC deliberates the
structural answer: move governance state onto its own ref lineage —
`refs/doctrine/gov` — so code branches carry code and governance carries
itself.

## Discussion

### The core move

`.doctrine/` authored corpus stops riding code history. It becomes a checkout
(materialized view) of a separate **orphan root lineage** at
`refs/doctrine/gov`, sharing the repository object store, advanced only by the
doctrine CLI under CAS. This adds a fourth ref class to SPEC-022's taxonomy:

| class        | example                          | mutability                          | writer             |
|--------------|----------------------------------|-------------------------------------|--------------------|
| coordination | `dispatch/<N>`, `edge`, trunk    | mutable, CAS                        | funnel verbs       |
| evidence     | `review/<N>`, `phase/<N>-NN`     | immutable, zero-oid CAS             | sync               |
| reservation  | `refs/doctrine/reservation/…`    | permanent, zero-oid CAS, remote     | reservation verb   |
| **governance** | `refs/doctrine/gov`            | **mutable linear WAL, CAS, remote-shareable** | **doctrine verbs only** |

### The plumbing already exists

Three shipped pieces are, incidentally, this system's primitives:

1. **Working-tree-free commit** (SL-199 D-B4 `commit_on_behalf`): scratch
   `GIT_INDEX_FILE` → `write-tree` → `commit_tree` → `update-ref` CAS. That
   *is* the gov write path — a gov write is a ref transaction, not a worktree
   mutation.
2. **Object-db sourcing** (`read_path_at`, SPEC-022 run-ledger contract):
   run-ledgers already tree-read from a branch tip, never the filesystem.
   Generalize: `show` reads from the gov tip.
3. **"Read via `show`, never raw files."** This discipline is unknowingly
   load-bearing for the migration: the CLI is already the sole sanctioned
   read/write interface, so the storage backend can swap underneath it without
   touching any consumer. The migration is invisible through `show`.

### Layout

```
refs/doctrine/gov          orphan lineage, linear, one commit per verb-write
.doctrine/                 MATERIALIZED VIEW — linked worktree of the gov ref,
                           gitignored by the code repo, same object store
.doctrine/state/           unchanged (runtime tier, gitignored, disposable)
```

Editing ergonomics preserved: agents and humans still edit `design.md` at the
same path. Verb writes commit-through immediately (one gov commit per verb,
CAS). Hand edits are picked up by a `gov sync`-class verb (dirty-detect →
commit) — the same posture as today's edit-preserving rules, now with a WAL
under it.

**Concurrency.** Entity files are per-agent disjoint in practice (today's
shared-`.doctrine/` reality already relies on this). CAS retry loop on the
ref; concurrent writes 3-way via `merge_tree` (entity-granular ⇒ almost always
trivial); a true conflict reports-and-halts. House invariants unchanged:
intent-journal, CAS, idempotent replay, CLI-sole-writer.

**Remote.** Push via refspec `+refs/doctrine/*:refs/doctrine/*` — the
reservation class already crossed this bridge. Consequence for RFC-014: every
clone in a fleet sees one governance corpus with no code-branch coupling;
orchestrators in different clones share memory/backlog/status live.

### What dissolves

- **R-5 becomes structural.** Worker worktrees are code-only; `.doctrine/`
  is not in their tree. The belt is kept as a debris tripwire, no longer
  load-bearing.
- **The split-brain family goes as a class** (IMP-174, IMP-236, IMP-258,
  memory orphaning). One gov tip is visible from the primary tree, the coord
  tree, anywhere. A status flip during dispatch lands on the gov ref, not on a
  branch the primary tree cannot see. Memory can never be squash-orphaned —
  it never rides a code branch.
- **Knowledge-trails-code becomes a pointer, not a commit-ordering
  discipline.** A gov commit carries `code_anchor = <oid>` naming the
  confirmed code commit. The four-bucket classifier (ADR-012 D2) mostly
  evaporates: knowledge no longer needs *projection* because it was never
  trapped in a code lineage.
- **Evidence cuts are born pure** — `phase/<N>-NN` stops filtering
  `.doctrine/`.
- **Confined-agent knowledge writes become clean.** A gov write is a ref
  transaction, so one MCP tool (`gov_record`-class) lets the confined
  orchestrator (SL-199) record memory/notes mid-dispatch without touching any
  checkout. Kills the "record memory on trunk, never in a fork" gotcha
  entirely.

### What it costs

- **Two-store atomicity.** Slice close moves a code ref and the gov ref
  consistently. Not new machinery — journal-before-mutation + idempotent
  replay is the existing answer, and reconcile is already a first-class verb.
  Accept brief inconsistency windows; detect via doctor.
- **PR review visibility.** Today `design.md` rides the same diff as the code
  it governs. Lost for migrated kinds — this drives the partial-migration
  position below.
- **Bisection ergonomics.** `git checkout <old>` no longer time-travels
  governance. Replace with the `code_anchor` mapping plus `--at <gov-oid>`
  reads. Partially a gain: gov history becomes a clean audit WAL instead of
  being interleaved through code commits.
- **Hosting blindness.** Forge UIs will not render `refs/doctrine/*`.
  Mitigate via `gov log`/`gov diff` verbs and the map server.
- **Migration surface.** The real price: install, boot-snapshot generation,
  the corpus scanner, and every path assumption.

### The favoured cut: migrate by access pattern, not wholesale

The witnessed failure family is almost entirely **knowledge-tier +
lifecycle-status** — things written *mid-flight from arbitrary trees*: memory,
backlog, case-notes, notes, slice status/phase state. Design artifacts
(design.md, specs, ADRs) are **change-coupled** — they *should* ride code
review next to the diff.

Favoured end-state is therefore split:

- **gov ref**: memory, backlog, knowledge records, lifecycle status,
  run-adjacent notes — everything global-by-nature and currently orphan-prone.
- **code tree** (as today): slice design/plan prose, specs, ADRs — everything
  review-coupled.

This captures approximately all the witnessed pain for a fraction of the
migration, and is honest about access patterns rather than ideological about
location. Wholesale migration remains available as a later stage if the
boundary chafes.

### Staging

1. **Shadow WAL** — verbs dual-write (files as today, plus a gov ref commit).
   Zero behaviour change; validates the write path, measures contention.
2. **Cut reads** for migrated kinds to gov-tip `read_path_at`; the
   `.doctrine/` paths for those kinds become the materialized view.
3. **Retire obsoleted belts** (R-5 stays as tripwire; the temporal classifier
   shrinks).
4. Optional: prose corpus, only if the split boundary proves wrong.

## Outcome

**Open.** Direction sketched; not yet deliberated. Open questions for the
descending discussion/slice:

- **OQ-1** — Single gov ref vs per-kind refs (`refs/doctrine/gov/memory`, …).
  Single = one WAL, one CAS point, whole-corpus snapshot oid; per-kind = less
  contention, messier atomicity. Lean single until contention is witnessed.
- **OQ-2** — Materialized-view staleness under multi-clone: refresh on every
  verb, on doctor, or explicit sync? Fetch-on-read is honest but costs
  latency.
- **OQ-3** — Does the coord run-ledger (`journal.toml`, `boundaries.toml`)
  stay on `dispatch/<N>`? Lean yes — it is evidence of a code-lineage run and
  belongs with it.
- **OQ-4** — Two-tier entities split across stores (TOML status on the gov
  ref, MD prose in the code tree)? Invisible through `show`, but a second
  boundary to explain. Only if lifecycle-status migration demands it.
- **OQ-5** — Jail interaction: the gov view is a linked worktree inside the
  project root — confirm the wall's `resolve_target` classification for agents
  whose cwd lands there (expected `Jail(gov-view)`, likely desirable).
- **OQ-6** — Atomicity contract at close: exact ordering of code-ref move vs
  gov-ref move, and the doctor check that detects a torn close.
