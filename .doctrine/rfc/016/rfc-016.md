# RFC-016: Zero-rescue dispatch: invariants into verbs, lineage rows

## Context

Dispatch correctness today rests on three enforcement tiers: **verbs with belts**
(SPEC-012 — enforced mechanism), a **prose cadence the orchestrator must hold**
(SPEC-021 D1 — the eight-step ordered contract, report-and-halt), and a **memory
corpus of recovery idioms** (checkout-import, re-anchor disjointness proofs, rtk
plumbing hazards) the agent must recall at the right moment and apply correctly.

RFC-011 instrumentation shows tiers two and three carry real cost — tokens, wall
time, and LLM autonomy: ~40–49k/phase of ceremony context, plus mid-run
**rescue** — the LLM recognising a quirk, retrieving the memory, applying the
idiom, sometimes wrongly. Operator burden compounds it: SPEC-022 carries seven
ref classes, a three-role candidate layer, and contracts the operator personally
enforces (RV-116: repair→close propagation rides sourcing discipline nobody
checks mechanically). History quirks — mixed single-operator / orchestrator /
worker deltas, code moved between machines mid-delta, loose worker or VT
coverage — leave lineage no recorded row describes, forcing archaeology at
close (the IMP-169 / IMP-236 family).

The question this RFC deliberates: how far can dispatch move to **zero-rescue**
— the LLM never diagnoses, never sequences, never recalls; it asks the tool
what's next, does it, and halts on refusal — with judgment reserved for what is
genuinely judgment (conflict content, red-verify triage, scope decisions)?

## Discussion

### The frame

Sort every piece of orchestrator/operator knowledge by *who could enforce it*:

| knowledge class | today | target |
|---|---|---|
| sequencing (cadence order) | prose + context | state machine in the binary |
| recovery idioms (computable) | memories, recalled | in-verb fallbacks |
| recovery idioms (judgment) | memories | report-and-halt (unchanged) |
| operator contracts (RV-116-class) | spec prose, operator-enforced | refusal + prescription in the gate |
| history variation | archaeology at close | lineage rows recorded at variation time |
| gotcha knowledge | preloaded memory corpus | point-of-need diagnostic text |

The goal is not zero LLM judgment — it is zero *routine* judgment and zero
*rescue archaeology*.

### A — Funnel becomes a state machine in the binary

Persist dispatch-run state as an explicit record (the CAS journal + boundaries
are already most of it); every funnel verb checks legality against it and
refuses out-of-order invocation naming the expected next verb. Add **`dispatch
next`**: emits the single prescribed action from current state. The
orchestrator prompt collapses to *run `next`, do what it says, report-and-halt
on refusal* — cadence knowledge moves from held context to point-of-need
output. SL-199 already made exactly this move for the confined arm (three MCP
tools, server-side belts, atomic conclude); this generalises the same machine
to the main-thread and subprocess arms so there is one funnel state machine,
three doors.

### B — Absorb mechanically-decidable recovery into verbs

Sort the rescue catalogue by "is the decision computable?":

- **corrupt-patch → checkout-import**: fully computable (batch-disjoint ∧
  coord==B ∧ S^==B are checks the verb already runs). Becomes an in-verb
  fallback, not an idiom.
- **moved-HEAD re-anchor**: computable (per-path byte-disjointness proof) —
  IMP-043, promoted from deferred nicety to load-bearing.
- **rtk proxy hazards**: exist only because the LLM shells raw git during the
  funnel. Remove the cause — ship read verbs (`dispatch delta`, status views)
  covering every funnel read, then prohibit shell git inside the funnel.
  Three memories retire.
- **not computable** (conflicting hunks, red-verify root-cause, scope
  widening): stays report-and-halt, by design.

### C — Operator-carried contracts become refusals with prescriptions

Every spec sentence of the form "the operator carries the burden" is a gate
waiting to be written. RV-116 is the archetype: the close-gate mechanically
checks the close_target contains the repaired review-surface tip and refuses
with a prescription ("source from the repaired candidate or cherry-pick
<oids>"). IMP-169 (recognise manual/external integration) and IMP-236
(direct-land records a trunk row) are the same move. Contract text stays in
SPEC-022 as *rationale*; enforcement lives in the verb. A contract only the
operator enforces is a memory with extra steps.

### D — Lineage recorded, never inferred

SPEC-022 already holds "coverage is reconciled, never inferred"; extend the
principle to history. Every **legal** variation gets a first-class recorded row
at the moment it happens: manual land → trunk row (IMP-236), hand-resolved
3-way → ingest row (IMP-127), external integration → recognition row (IMP-169),
cross-machine transport → a `dispatch bundle export/ingest` verb pair carrying
delta + metadata together, so the receiving side gets rows, not a bare diff.
Downstream gates consume rows mechanically. The contrapositive is the belt: a
variation that cannot get a row is refused **at the point of variation**, not
discovered at close.

### E — Gotcha memories migrate into diagnostics

`dispatch status --prescribe` / doctor-class output: current state, divergences,
one prescribed action each — with the memory *content* embedded in the refusal
or diagnostic text at the moment of relevance. Preloaded corpus knowledge →
delivered-when-needed tool output; the same economics as A. The dispatch memory
corpus shrinks to rationale (why the belt exists), the skills shrink to "run
`next`".

### Concept count (the SPEC-022 half)

Seven ref classes are tolerable when nobody has to *hold* them — `next` and the
gates hold them. The one real vocabulary cut: candidate role sourcing. Keep the
`review_surface` / `close_target` distinction (they filter differently) but make
sourcing **default-automatic** — close_target sources from the repaired
review_surface unless explicitly overridden. Burden gone, expressiveness kept,
no storage remodel.

### Acceptance — the memory-blind orchestrator test

A fresh orchestrator with **zero dispatch memories loaded** completes a standard
run *plus* the top-5 quirk scenarios purely by following verb outputs. RFC-011's
case-notes give the priority order for free: mine them for which quirks actually
burned tokens, mechanise in that order. Done = the benchmark passes and the
retired memories are archived.

### Alternatives considered

- **Status quo + better memories.** Cheaper per item, but RFC-011 evidence says
  recall-at-the-right-moment is precisely the failure mode; better prose does
  not fix a delivery-time problem.
- **One mega-verb (`dispatch drive`) instead of a state machine + `next`.**
  Rejected: collapses the report-and-halt seams the funnel depends on; `next`
  keeps each verb's belt and the halt discipline while removing sequencing
  knowledge.
- **Delete ref classes to cut concepts.** Rejected: each class is
  scar-tissue-justified (RV-030, SL-067); the burden is *holding* them, which
  A/C/E remove without a remodel.

## Outcome

**Open.** Direction proposed; for the descending slice(s):

- **OQ-1** — `dispatch next` contract: prescriptive oracle only, or also the
  legality gate inside each verb (lean: both — `next` prescribes, verbs refuse).
- **OQ-2** — where run state lives: extend the journal/boundaries records or a
  new run-state record; one machine shared by all three arms (main-thread,
  subprocess, confined) or per-arm projections.
- **OQ-3** — `dispatch bundle export/ingest` scope: what metadata must travel
  for the receiving side to mint honest lineage rows (base, scope selectors,
  verify evidence?).
- **OQ-4** — candidate auto-sourcing semantics: default close_target ←
  repaired review_surface; what the explicit override looks like; interaction
  with admit-by-OID.
- **OQ-5** — memory-blind benchmark harness: how measured, which top-5 quirk
  scenarios (mine RFC-011 case-notes), where it runs (CI-able?).
- **OQ-6** — memory disposition: which dispatch memories retire, which remain
  as rationale attached to belts (`memory status` lifecycle for the retired).
- **OQ-7** — read-verb coverage: enumerate every funnel read the LLM currently
  shells; any gap blocks the no-shell-git-in-funnel rule.

### Sequencing from the RFC-011 evidence (2026-07-23)

OQ-5 asked which quirks to mechanise first; the case-notes are now mined
(`.doctrine/rfc/011/case-notes-analysis.md`, all 2313 lines, ranked freq×impact).
The evidence **reprioritises the moves against the RFC's own ordering**: the top
token-burners are false-reds and unhelpful refusals (moves **B/C**), not
cadence-holding (**move A**). Sequencing cost is real (~40–49k/phase ceremony)
but amortised; the acute, repeated burns are diagnosis of *environmental* red.
So B/C + funnel hygiene land **before** A, and A's memory-blind benchmark (OQ-5)
is measured against the cleaned baseline B/C produce.

Already landed — not in scope below:

- phase-status split-brain (freq 7) → IMP-272 **resolved/fixed** (IDE-028 idea open).
- split-lineage close (freq 4, move D) → IMP-127 / IMP-236 **resolved** via
  SL-211 / SL-212. Residual tail: IMP-174, IMP-201 (authored-divergence / bundle).

**Cluster 1 — honest refusals + false-red elimination (moves B+C), top ROI, slice first.**
Split into two tight, separately-auditable slices by move:

| case-note | freq | move | slice | backlog |
|---|---|---|---|---|
| selector under-declaration | 8+ | C — Refused.detail names paths + plan-time lint | **SL-224** | IMP-256 |
| import empty Refused.detail | 4 | C — same seam | **SL-224** | GAP |
| worker_commit false-red (stale PATH binary) | 6+ | B — gate runs workspace binary, not PATH | **SL-225** | ISS-218 (IMP-270 dup-closed) |
| e2e goldens false-red under worker marker | 7+ | B/E — marker-aware skip | **SL-225** | CHR-044 |

Both slices' fixes are true *false-reds / refusals* (a green delta shown red, or
a halt that won't say why) and survive Cluster 2 intact — read-verbs do not touch
how the gate resolves its binary or how the worker's own `cargo test` trips the
marker.

**Cluster 2 — `dispatch next` (move A) + no-shell-git reads + memory-blind benchmark, slice second.**
No single case-note isolates cadence as a top burner, so A is the *enabler* for E
and the benchmark rather than a burn-reduction in its own right. Touches SPEC-021 /
SPEC-022 prose → routes through a **Revision**, then a slice, measured against the
baseline Cluster 1 leaves behind. Absorbs the **coord-worktree reverse-diff**
(case-note #2, freq 6 — funnel ref-advance leaves the coord tree showing landed
files as staged deletions; **ISS-234**): the durable fix is read-verbs covering
every funnel read + a no-shell-git-in-funnel rule, which makes the tree state
irrelevant — *not* an interim auto-sync that Cluster 2 would then retire. This is
the first move-E / OQ-6 memory-retirement (the checkout-import recovery idioms
retire when shell-git leaves the funnel).
