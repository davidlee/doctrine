# IDE-049: Kanban Time

(confirmation bias)[https://webaligo.bearblog.dev/kanbanize-now/]

I think the trick is just .. 
have user-definable states with WIP limits 
and make the state policy (e.g. what must go through UAT) 
expressible (e.g any work item with / without a given tag). 

There's already a dependency graph, it just needs a model of 
a queue to overlay it onto, and a query over git history, 
to compute the rest.

 * model / derive throughput, cycle time, etc
 - history-informed projection
 * make work visible (web serve kanban)
 - card age based ordering / warn
