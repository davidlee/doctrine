# ISS-498: Hymn harness band is unreachable — nothing passes --harness

The hymn cascade's `harness` band resolves correctly on demand and is never
asked for, so its content is shipped-but-dead — the `stage` band's twin of this
gap is `ISS-447`.

## Evidence

- `.pi/extensions/doctrine/index.ts:8` (generated by `doctrine boot install`)
  resolves `prompt resolve --role orchestrator`. No `--harness`.
  `.claude/settings.json:27` is the same, and
  `install/agents/pi/dispatch-worker.md:36` bakes `{{ prompt resolve --role
  worker }}` — also no `--harness`.
- A tree-wide grep for `--harness` finds it only in `src/commands/prompt.rs`
  (the flag itself) and its tests. Nothing selects the band.
- Confirmed by resolution: `prompt resolve --role orchestrator` omits
  `install/hymns/harness/*`; adding `--harness claude` includes it. The band
  works — it is simply never selected.
- Consequence: `install/hymns/harness/{claude,cursor}.md` reach no agent context
  by any current path, and there is no `harness/pi.md` to miss.

## Why it matters now

This repo's harness-specific guidance has had to live outside the cascade, in
harness-owned files: `CLAUDE.md` `## Research` (Claude) and
`.pi/APPEND_SYSTEM.md` (pi). That split is right while the band is dead —
mechanism is harness-specific (`POL-003`) — but the cascade is the designed home,
and the harness band is its only harness-neutral one.

The pi half also carries a ship question: the *generic* pi posture (prefer the
native subagent facility; name model + thinking level on every spawn) belongs on
a shipped surface per `mem.system.governance.ship-usage-guidance-to-clients`,
while "don't use `./scripts/pi-*`" is doctrine-dev-only. Only the latter is local.

## Candidate remedies

1. Extend the boot snapshot's floor directive to name the harness as well as the
   model (`install/model-band.md` is the existing precedent), so an agent
   self-identifies and resolves `--harness <its harness>`. No Rust, symmetric
   with the model band, no wiring change.
2. Pass `--harness` from the wirings that already know it: the generated pi
   extension and `.claude/settings.json`. Precise, but adds a per-harness
   migration to the `RESOLVE_EMIT_ARGS` legacy-args handling in `src/boot.rs`.
3. Fold the band into the role band if it earns nothing once (1) is priced.
