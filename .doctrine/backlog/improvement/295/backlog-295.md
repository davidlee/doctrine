# IMP-295: Spec-coverage assessment: skill + deterministic support for gap analysis and boundary-setting across C4 levels / product altitudes

## Motivation

We have skills to *author* a spec at a target you point them at (`/spec-product`,
`/spec-tech`), and skills to formalise individual requirements in the reconcile
loop ([[IMP-096]]). What we do **not** have is any support for the step *before*
authoring: deciding **what deserves a spec, what is already covered, and where
the boundaries should fall.**

Concretely, when facing a subsystem (e.g. the graph — see [[CHR-046]]) an agent
has no guided way to answer:

- **Coverage** — which parts of this capability are already governed by an
  existing PRD / tech spec / ADR, and which are dark? Where does coverage overlap,
  conflict, or leave seams?
- **Boundaries** — how should the surface be carved into specs? What belongs at
  which **product altitude** (PRD) and which **C4 level** (context / container /
  component) for the tech spec? One spec or several? Where do the edges sit so
  specs stay cohesive and don't bleed into each other?
- **Descent** — how do the chosen boundaries line up with the existing
  ADR/spec/slice corpus so new specs slot in rather than duplicate.

This is a systemic deficit: spec *coverage* is currently ad-hoc and depends
entirely on the authoring agent's judgement, with no artifact recording what was
considered in-scope vs. deliberately excluded, and no way to detect an
un-governed subsystem before it drifts.

## Direction (to be designed, not committed)

Two complementary axes, likely both:

- **Skill support** — a coverage/boundary-assessment skill (or an extension to
  the routing gate / `/spec-product` front-matter) that: inventories existing
  governance touching a named surface, maps it against the surface's real extent,
  surfaces gaps/overlaps, and proposes a spec-boundary decomposition keyed to
  product altitude and C4 level. Output is a reviewable coverage map that feeds
  `/spec-product` / `/spec-tech`.

- **Deterministic aids** — mechanisms that make coverage legible without an agent
  re-deriving it each time. Candidates to evaluate:
  - memory globs / a coverage index over the entity corpus (which specs/ADRs
    claim which surfaces);
  - autogenerated documentation / contracts from source (the C4-container/
    component inventory) to diff against declared spec coverage;
  - a `doctrine` read verb that reports spec/ADR coverage for a path or subsystem.
