# ADR-022: Evidence ownership between peer corpora

<!-- Reference forms: doc/glossary.md § reference forms. -->

## Context

Doctrine repositories have started to come in pairs. Oubliette — the confinement
mechanism the capsule work rests on (`ADR-020`) — adopted doctrine and now keeps a
corpus of its own. Before it did, evidence about **its** machinery was minted
**here**, and four records still are:

| record | subject | how it cites across |
| --- | --- | --- |
| `EVD-018` | its netns boot probe, 9/9 | names the probe script |
| `EVD-019` | its freshness probe, 22/22, and the figures | names the probe script |
| `EVD-020` | its two-capsule probe, 28/28, and the figures | names the probe script |
| `EVD-025` | host-integration and macOS portability cost | two `../microvm-spike/docs/…` paths |

Its own probe documentation cites the first three back by id. The graph already
crosses the repository boundary in both directions, and nothing says which end
owns a claim.

**The drift is not hypothetical.** `EVD-019` leads with *8.31 s to a usable fresh
capsule*. `oubliette:EVD-002` — *Time-to-interactive is about two minutes, not
8.31 s* — establishes that the two figures come from different runs and must not
be quoted as one result. Both records are `captured`, neither links the other, and
`QUE-217` (*which casual capsule backends should complement hardened microVMs*)
reads this side. `EVD-025` is the second half of the same problem: its body cites
`../microvm-spike/docs/eval-macos.md`, a path that climbs out of one working tree
into another, resolves only from a directory neither repository declares, and
names the peer under a checkout name it no longer has.

Oubliette settled its half in `oubliette:ADR-003`, and recorded in
`oubliette:CHR-012` that everything still owed sits on this side. That is the shape of the
problem: **a rule authored in one corpus binds one corpus.** Two repositories that
cite each other need the rule stated at both ends, and only doctrine can state
doctrine's.

**Two established senses of one word.** `SPEC-018` is titled *Cross-corpus
relation contract* and means edges spanning entity **kinds** within a single
project. The axis this ADR governs spans **repositories**. To avoid overloading a
term already load-bearing in the relation contract, this ADR fixes **peer corpus**
for the second sense and leaves `SPEC-018`'s usage untouched.

## Decision

**We will treat a peer corpus as a declared counterparty, and decide which corpus
mints a record by the record's subject.** Four clauses.

### 1. A peer corpus is declared, never inferred

A repository that cites another doctrine corpus **declares that peer in owned
configuration** — a name bound to an identity, written down once. Nothing about a
citation resolves through relative directory layout, sibling-checkout presence on
disk, or a working-tree name.

This is `POL-002` applied, not an aesthetic preference. A rule that resolved
`../<some-directory>` would make doctrine load-bear on one host's working-tree
arrangement — the type case the policy forbids, and precisely what `EVD-025`'s two
paths do today. Declaration is also the enabling condition for clauses 3 and 4:
neither a citation form nor a lint can be checked against a peer nobody named.

**Deliberately not decided here:** the declaration's schema, and whether doctrine
ever *reads* a declared peer's corpus rather than merely naming it. This clause
fixes that the peer is named in configuration doctrine owns. `IMP-441` decides the
form, and may decide that naming is all doctrine ever does.

### 2. The subject decides which corpus mints

An observation whose subject is a **peer's machinery** — a probe run there, a
figure taken off its host, a refusal it exercises, a cost of that mechanism itself
— is minted in **the peer's** corpus. This corpus cites it across by id and does
not re-mint it.

An observation whose subject is **this corpus's own choice** — a selection between
mechanisms, an adoption or portability cost, a comparison between tiers — is
minted **here**, even when every datum in it was read off the peer. `EVD-025` is
the type case and is correctly placed.

The test is **what is the subject**, not who ran it and not who wanted the answer.
Wanting a number is the ordinary case, and citation is what it is for.

Where the two readings are genuinely close — *the cost of a mechanism* against
*the cost of adopting it* — the tie-break is **which repository would have to
change if the claim turned out to be wrong.**

### 3. A citation names a declared peer and an id — a bare peer id is forbidden

A record citing across the boundary names the peer by its **declared name** and
the target by its **entity id**, written adjacently so neither can be read without
the other: `oubliette:ADR-003`. Where it points at a file rather than a record, it
uses a **peer-relative path** qualified the same way.

Never a relative path that climbs out of a working tree, and never a checkout
directory name — both are properties of one machine's disk rather than of either
repository.

**And never a bare id.** The failure here is not untidiness, it is a silently
wrong resolution. Peer corpora number their own kinds independently, so ids
overlap in number and never in meaning. Every id needed to describe this ADR's own
subject matter already collides:

| written bare | resolves here to | meant |
| --- | --- | --- |
| `ADR-002` | *Global orientation memory class* | the peer's *ledger is a closed archive* |
| `ADR-003` | *Canonical change loop* | the peer's *Evidence has one home* |
| `EVD-002` | *`claude -p` exposes token usage metrics without usage billing* | the peer's *time-to-interactive is two minutes, not 8.31 s* |
| `CHR-012` | *Fold `KindPartition` prefixes onto `kinds::`* | the peer's chore recording this ADR's whole subject |

Four for four, and every one of them resolves — so nothing reports a problem. A
dangling citation is a warning; a colliding one is a wrong answer delivered
confidently.

The qualifier is fixed here because prose needs a form today. Whether it also
becomes a resolvable reference the tooling understands is `IMP-441`'s to decide.

### 4. Records predating the rule are not migrated; their disputes are made visible

`EVD-018`, `EVD-019`, `EVD-020` and `EVD-025` stay where they are, and the peer
goes on citing the first three by id.

A re-mint is a fresh claim wearing an old record's clothes. A record's value is
that it survived contact with the run that produced it; moving it buys a tidier
index and spends exactly that. `oubliette:ADR-002` reaches the same conclusion
one corpus over, and this ADR is not going to contradict it in order to be neat.

**What is owed instead is the dispute, stated on both records.** Where a peer's
corpus contradicts one of ours, the contradiction is written on ours too, and ours
is left standing with its dispute named — rather than silently corrected next door
and read stale here. `CHR-069` is that repair for `EVD-019`, and the citation-form
repair for `EVD-025`.

**It is not stated as a relation, and the reason is worse than a refusal.** The
vocabulary has the label — `disputes` / `disputed_by` are in `RELATION_RULES`. What
it does not have is a target namespace wider than one corpus. So:

```
$ doctrine link EVD-019 disputed_by EVD-002
```

does not fail. It resolves `EVD-002` locally, to a record about `claude -p` token
metering, and writes a confident assertion that is simply false. A verb that
refuses would be safe; this one succeeds at the wrong thing.

**Where the citation goes instead.** A knowledge record carries an `[evidence]`
block — `supports` / `contradicts` / `notes` — of **free-text** citations, parallel
to and independent of its validated `[[relation]]` rows. Free text is exactly what
a peer citation needs: it is structured enough to be enumerated and greppable,
and it resolves nothing, so it cannot collide. A peer dispute is written there in
the qualified form of clause 3, and repeated in the body where a reader will meet
it. Not in a relation, until `IMP-441` says a relation can mean this.

## Consequences

### Positive

- One home per claim. A figure has one place to be edited and one place to go
  stale, across the repository boundary that both corpora were previously silent
  about.
- Anything reading across — `QUE-217` today — gets a declared name and an id that
  means the same thing from any directory, instead of a path built out of
  somebody's checkout layout.
- The declaration in clause 1 is the missing precondition beneath both owed
  mechanisms: `IMP-440`'s lint gets something to key on, and `IMP-441`'s qualified
  reference form gets a namespace that is not a filesystem.
- Stating the rule here makes the pair symmetric. `oubliette:ADR-003` and this
  ADR bind their own ends, which is the only arrangement in which either is
  enforceable by the repository that would have to enforce it.

### Negative

- **The rule is prose and nothing refuses a violation.** No doctrine mechanism
  sees two corpora, so clause 2 is checked by a human reading it. See
  *Verification*.
- **Four grandfathered records make the rule read as *mostly*.** Anyone arriving at
  `EVD-019` from this side still meets the 8.31 s headline first, dispute sentence
  or not.
- **Cross-boundary citation stays invisible to the graph.** `backlinks`,
  `relation census`, the concept map and every reachability question stop at the
  repository boundary, so the rule buys coherence in prose and nothing in the
  graph.
- **Clause 2's boundary is a judgement**, and the tie-break is a heuristic rather
  than a test. Records will be argued either way.
- A declared peer is one more piece of configuration that can go stale, and
  nothing yet detects a declaration pointing at a corpus that moved.

### Neutral

- No ids move and no corpus is re-sequenced. Both corpora keep their own `EVD`
  numbering, which already overlaps in number and never in meaning.
- This ADR governs which **corpus** mints a record. It says nothing about where a
  figure lives inside the peer, which is the peer's own business.
- **Out of scope by choice:** `oubliette:ADR-003` clause 4 carries two probe
  disciplines up into its evidence convention — *assert both directions*, and
  *name what the run deliberately does not prove*. Both are sound and neither is a
  cross-repository question; they are general evidence-quality disciplines whose
  home is `SPEC-019`'s `EVD` facet (`datum` / `provenance` / `confidence`, which
  has nowhere to put either). Bundling them here would make this ADR about two
  things. Tracked separately.

## Verification

**Written, and enforced by nothing.** Stated plainly rather than claimed, clause
by clause:

- **Clause 1 — declaration:** unimplemented. No configuration surface for a peer
  exists yet; `IMP-441` carries it.
- **Clause 2 — ownership:** unenforced. No doctrine mechanism reads two corpora.
  `IMP-440` is the cheap version — scan this corpus's `EVD` bodies for a declared
  peer's markers and report any record whose subject looks like the peer's
  machinery rather than doctrine's choice. Report, not refuse: `EVD-025`
  legitimately cites the peer while its subject stays doctrine's, so a hit is a
  question for a human.
- **Clause 3 — citation form:** unenforced, and **invisible to the gate that looks
  most like it would catch it.** `doctrine check`'s prose-citation scan reports
  *unresolved* ids; a bare peer id resolves, so it is silent by construction —
  verified against this ADR's own four collisions, none of which the scan
  reported. The mechanical halves are worth failing on rather than warning: a
  relative path climbing out of the tree, and a retired checkout name, are always
  wrong under this ADR. `IMP-440`.
- **Clause 4 — the dispute:** carried as free text in the record's `[evidence]`
  block and repeated in its body. Validated by nothing, invisible to `backlinks`
  and `relation census`, and not settable through a verb — `knowledge edit
  evidence` exposes `datum` / `provenance` / `confidence` only, so the citation is
  hand-authored into the TOML. `IMP-441` decides whether a relation ever means
  this; until it does, the `disputes` label is a trap here, not an option.

Two things would make this real, and neither exists: a peer-aware lint for clauses
2 and 3, and a peer-aware target namespace for clause 4. Recorded as owed rather
than claimed.
