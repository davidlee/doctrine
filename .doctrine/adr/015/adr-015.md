# ADR-015: Multi-dimensional priority scoring

## Context

Doctrine's `survey` and `next` surfaces rank work by actionability and a raw
inbound-reference count named `consequence`. That count is structurally honest but
semantically weak: an item referenced by five low-value ideas outranks, or ties,
one that gates a smaller number of high-value slices. IMP-118 asks for priority to
reflect the authored value, estimate, and risk facets already present in the
corpus, plus operator-tunable coefficients.

This decision is project-wide rather than slice-local. Once adopted, `score`
becomes a reusable ordering primitive for priority surfaces, explain output, and
future graph views. The policy therefore belongs in an ADR; SL-133 implements it.

Adjacent doctrine constrains the shape:

- ADR-001 requires risk parsing to be available below command-tier callers; the
  implementation must not make a leaf or engine module import `backlog`.
- ADR-004 forbids storing reverse/derived relation data in authored entity files;
  priority consequence is derived from the outbound relation graph at read time.
- The pure/imperative split requires scoring to be pure over scanned authored data,
  config, and an assembled graph; disk access remains at the scan/config seams.

## Decision

We will replace raw inbound-reference consequence with a multi-dimensional
floating-point priority **score**:

```text
base(N)        = value_dim(N) + risk_dim(N)
consequence(N) = leverage(N) + optionality(N)
score(N)       = base(N) + consequence(N)
```

### 1. Base dimensions

`value_dim` is the authored value adjusted by the global value coefficient, kind
and tag coefficients, divided by `est_cost`:

```text
value_dim = (coefficients.value × value × kind_weight × tag_multiplier) / est_cost

est_cost = lower + β(upper − lower)         # resolved estimate claim (skew β, default 0.65;
                                            #   ladder tier per Estimate-source resolution)
         = point projection                 # no anchored claim; sizing evidence in an
                                            #   anchored component (see Estimate-source resolution)
         = max_upper(corpus) + margin       # bare (no claim, no fed projection;
                                            #   margin default 1.0)
         = 1.0                              # empty corpus fallback

tag_multiplier = max(0.0, 1.0 + Σ (tag_coefficient − 1.0))   # summed over the entity's tags
```

`est_cost` replaces the former plain estimate **midpoint** divisor. With a
resolved estimate claim, cost skews between the bounds by β (β = 0.5 recovers the
legacy midpoint — INV-1). Bare items anchor on the corpus `max_upper` plus a `margin`, a
data-driven divisor that dominates every **asserted** range (INV-2, restated by
REV-026): projected costs may exceed or undercut the bare anchor — evidence, not
the default, then sets the divisor. The original anti-inversion intent is
preserved exactly: a bare item with *no sizing evidence* keeps the dominating
divisor, so it can never be priced cheapest and outrank everything (the ISS-057
inversion). `est_cost` is floored at `EPSILON` (no div-by-zero — INV-3; see also
the positivity axiom below). β and margin are operator knobs (§4,
`[priority.estimate]`).

The tag term is a **delta-from-default** multiplier: each tag contributes its
coefficient's *excess over the unit default* (`tag_coefficient − 1.0`), so a tag
at the default `1.0` is inert, a promoting coefficient (`> 1.0`) lifts the
multiplier, and a demoting coefficient (`< 1.0`) lowers it. The multiplier is
floored at `0.0` so a stack of demoting tags suppresses rather than inverts the
sign of `value_dim`. (A literal `Σ tag_coefficients` is rejected: it would inflate
the score for every default-coefficient tag merely by tag count, and zero
`value_dim` for the untagged majority.)

`risk_dim` is the authored risk exposure adjusted by a risk coefficient:

```text
risk_dim = exposure × risk_coeff
```

Absent authored data collapses to an identity/floor rather than an error:

- absent value on a value-bearing kind ⇒ `value = 1.0` (`DEFAULT_VALUE`,
  SL-177) — unvalued work scores at unit value rather than disappearing from
  `value_dim`; with comparison evidence (RFC-019), absent authored value
  resolves through projection first (see *Value-source resolution*), and
  projection's unanchored fallback reproduces this same default;
- absent estimate claims ⇒ resolves through the estimate constraint
  layer's projection first, then asserted-tier priors (see *Estimate-source
  resolution*); with no ladder hit, `est_cost = max_upper(corpus) + margin`
  (the bare anchor; `1.0` when the corpus is empty);
- absent risk facet ⇒ `risk_dim = 0`;
- absent tags / all-default-coefficient tags ⇒ `tag_multiplier = 1.0` (the
  identity); a coefficient that differs from the `1.0` default shifts the
  multiplier by that delta, and the multiplier floors at `0.0`.

The risk model is the existing likelihood × impact exposure model; this ADR does
not create a new risk vocabulary.

### Value-source resolution (REV-024, RFC-020)

The `value` input to `value_dim` resolves per item by the epistemic
authority ladder, first hit wins:

1. **Anchored claim** — the resolved pin- or human-tier anchor claim from
   the comparison ledger (`value pin` / `value set --rater human`). Wins
   outright and additionally acts as a point anchor in the comparison
   constraint layer, propagating bounds to items compared against it.
   Pin outranks human claim within the tier resolution.
2. **Comparison projection** — items with comparison evidence but no
   anchored claim take the deterministic point projection within their
   derived bounds (RFC-019 constraint layer). Anchors feeding the
   constraint layer come from pin/human tiers only — agent-tier magnitudes
   never shape projection (anti-laundering, RFC-020).
3. **Agent-tier claim** — an attributed agent claim resolves as a prior
   below projection: a number, not an answer.
4. **Migrated-tier claim** — an unattributed magnitude imported from a
   retired `[value]` facet (rater = migrated, observed-at only); ranks
   below attributed agent claims.
5. **Unmigrated `[value]` facet** *(transitional)* — consulted only when
   zero claim rows exist for the item; presence fires an `UnmigratedFacet`
   finding. This rung deletes when both domains have migrated (RFC-020
   Phase 2 exit criterion).
6. **Default** — `DEFAULT_VALUE = 1.0`.

Same-tier conflict never resolves silently: distinct active magnitudes in
the winning tier resolve to their arithmetic mean over the full row
multiset, render the disagreement interval as bounds, and fire a
`ClaimConflict` finding (a conflicted pin is a *contested pin*); resolution
is a human appending an explicitly superseding row. A pin/human anchor
conflicting with comparison-derived bounds remains a surfaced
contradiction, not a silent win. Resolved values, bounds, and projections
are derived at read time from the ledger; they are never authored to disk
(the same posture as scores). Claiming value on a non-value-bearing kind
warns: the capture is lossless but scoring-inert — a record's worth is
derived from what it unlocks (REV-022 Q1, unchanged posture).

### Estimate-source resolution (REV-026, SL-222)

The `est_cost` input to `value_dim` resolves per item by the T3 epistemic
authority ladder over estimate claims — **source precedence only, no
numeric-dominance claim**; first hit wins:

1. **Anchored claim** — a resolved pin or human-tier estimate claim
   (conflict means included): the claim's operative cost
   (`estimate::operative_cost(bounds, skew)`, EPSILON-floored). Anchored
   claims also anchor the estimate constraint system, propagating cost
   bounds to items compared against them — the two seams the authored
   facet previously occupied, now attributed and dated.
2. **Cost projection** — items with sizing evidence in an anchored
   component take the deterministic point projection within their derived
   bounds (RFC-019 constraint layer; non-Gauge provenances only; EPSILON
   floor at the consumption seam).
3. **Agent-tier claim** — a resolved agent-authored claim's operative
   cost: a prior below projection, above migration.
4. **Migrated-tier claim** — a resolved `rater = migrated` claim's
   operative cost (unattributed imports sit at the bottom of asserted
   evidence; migration never mints a pin).
5. **Bare anchor** — items with no ladder hit take the dominating
   divisor (INV-2 below; `1.0` empty-corpus fallback).

During the migration window an unmigrated `[estimate]` facet resolves
between rungs 4 and 5 (consulted only at zero claim rows; presence fires a
loud finding regardless of consumption); the rung and the facet read paths
delete at the migration census — REV-024's Phase-2 rung-deletion clause is
recorded as fired by this REV. A never-migrated corpus re-ranks
deterministically (facet-valued items fall to the bare anchor) with loud
findings naming `scripts/migrate_estimate_facets.py` and
`estimate set --rater human` as the remedy.

Same-tier conflict resolves to the per-field mean over the winning-tier
multiset with the operative-cost conflict interval surfaced as a finding —
corroboration and conflict are distinguished, never silent. The authored
`[estimate]` facet is retired as an input: `estimate set` appends ledgered
claims; `estimate pin` is the operator-policy override, now attributed and
governed (interactive-TTY, worker-refused write class). The "records
anchor too" posture narrows to anchored-tier claims — a records-anchor
delta disclosed as class-b behaviour change.

**INV-2 restated for the claims era**: the bare anchor is computed over
**every active unlensed estimate-anchor row's upper** — any tier, losing
tiers and individual conflict rows included, plus transitional unmigrated
facet uppers — and therefore dominates every active asserted range by
construction; projected costs may exceed or undercut it; a bare item with
no evidence keeps the dominating divisor (the ISS-057 anti-inversion
intent preserved exactly).

**Gauge never divides** (unchanged, claim vocabulary). Anchor-free
components receive only a conventional, render-only gauge ordering
(spacing `gauge_step`, centred on the bare anchor). Conventional
magnitudes may fill a numerator, never a denominator: gauge-tier
placements are never fed to `est_cost`. A gauge-masked item carrying an
asserted claim resolves at its claim tier — an asserted range beats a
conventional gauge — else it scores at the bare anchor, and surfaces must
never imply otherwise.

**Positivity axiom** (unchanged, claim vocabulary). The estimate feasible
region is order constraints + point anchors + `c > 0`. Settle-cost is a
nonnegative physical quantity: payload validation enforces `lower ≥ 0` at
capture (`estimate::validate`, the single source), every anchor is
strictly positive (operative costs floor at `EPSILON`) and every fed
projection is strictly positive (`EPSILON` floor at the consumption seam).
Sizing evidence packing items below a small anchor therefore compresses
into `(0, anchor)` — a forced consequence of evidence + positivity; the
spacing within the interval is convention, disclosed by provenance labels
and bounds display.

**Fixed policy, not a knob.** The estimate ladder is policy.
`demote_agent_evidence` widens to estimate claims — when set,
agent/migrated-tier resolved costs leave sizing probe-eligibility intact;
when unset they retire it. Probe targets require anchored-tier claims.

An asserted claim that conflicts with sizing-derived bounds is a surfaced
contradiction (the likeliest defect is a stale estimate — loudness is a
feature), not a silent win. Projected costs and bounds are derived at read
time from the comparison ledger; they are never authored to disk (the same
posture as scores and projected values).

### 2. Two-pass scoring model

Scoring has two pure phases around the existing graph build:

1. **Base pre-pass** — compute each node's base score from its own authored facets,
   kind, and priority config, plus one corpus-level scalar threaded in as a pure
   input: `max_upper`, the bare-item cost anchor (an impure scan computes it once,
   the pure base fn consumes it — date/uid pattern). This phase has no graph access
   and is safe to use as the graph mint tiebreaker.
2. **Consequence post-pass** — after the graph is assembled, compute consequence
   from graph edges and already-computed base scores.

The graph's structural mint order must not use graph-derived consequence. Mint uses
`base` only; display surfaces may sort by the final `score` after the graph exists.

### 3. Consequence classes

Consequence has two edge classes with different semantics.

**`needs` leverage is recursive.** If `A needs B`, then completing `B` unlocks `A`;
therefore `B` accrues a coefficient-weighted share of `A`'s base value and the
value recursively unlocked by `A`. `dep_coeff` is a recursive retention factor in
`[0, 1]`, where `0` (and any value clamped from `≤ 0`) explicitly DISABLES leverage;
above `0`, along a single path depth decays as `dep_coeff^k`.

Leverage is intentionally a finite path-sum over the finite needs graph. In a
reconvergent diamond, the shared downstream node contributes through each path.
`dep_coeff <= 1` gives per-path retention; it does not bound total magnitude under
fan-out. Large path-sums are visible through explain output rather than silently
reinterpreted as deduplicated reachability.

A diagnosed `needs` cycle is malformed authored data. The scoring read must still
terminate: cycle components are condensed for scoring, intra-component needs edges
contribute zero, and the cycle remains surfaced as an authoring error.

**Reference/lineage optionality is one-hop.** Work/lineage references contribute a
flat optionality share from direct referencers only. These overlays are
cyclic-capable and associative, so recursive accumulation over them is not part of
this policy. `ref_coeff` is a flat non-negative weight.

**`after` / seq is structural, not a score weight.** Sequence edges order work; they
are not a third consequence dimension and have no coefficient. If later evidence
shows structural sequencing is insufficient, a future ADR or amendment may add a
separate seq-weight policy.

### 4. Config contract

Doctrine owns a `[priority]` config section with these policy-level roles:

```toml
[priority.coefficients]
# value, risk

[priority.kind_weights]
# kind-name -> multiplier

[priority.tag_coefficients]
# tag -> multiplier

[priority.consequence]
# dep_coeff, ref_coeff

[priority.estimate]
# skew (β, [0,1], default 0.65), margin (≥ 0, default 1.0),
# gauge_step (render-only gauge spacing, default 0.25)

[priority.value_fit]
# projection knobs (implementation-owned)
```

Unknown keys are tolerated for forward compatibility. Numeric default values,
example weights, maximum clamp constants, and the exact malformed-value recovery
mechanics are implementation-owned. The durable domains are policy:

- value/risk/kind/tag coefficients do not invert priority;
- `dep_coeff` is a recursive retention factor in `[0, 1]`, with `0` (and any clamped
  `≤ 0`) the explicit disable sentinel;
- `ref_coeff` is flat and non-negative;
- seq has no coefficient;
- value-source resolution order (pin > human claim > projection > agent
  claim > migrated claim > unmigrated facet (transitional) > default) is
  fixed policy, not a knob; claim resolution and projection are
  deterministic given (ledger, config); conflict and contradiction
  surfacing cannot be suppressed by configuration;
  `[priority.compare] demote_agent_evidence` widens to claims: when set,
  agent- and migrated-tier resolved values never retire elicitation —
  the item stays probe-eligible;
- estimate-source resolution order (authored → projected → bare anchor) is
  fixed policy, not a knob; projection is deterministic given (ledger,
  config, anchors); gauge-tier magnitudes cannot be configured into the
  divisor;
- β, `margin`, and `gauge_step` are operator knobs; an edit to any re-runs
  estimate projection → resolved costs → value determinacy (one reprobe
  dynamic spans both domains).

Coefficient and tag tuning is an expected, supported UX for shaping priority order
to a particular purpose. Changing global value-vs-risk weights, kind weights, tag
coefficients, or the tags authored on items changes the derived score immediately;
it is configuration/data authoring, not a code change and not an ADR amendment. The
system therefore promises cheap retuning plus explainability, not a single stable
priority sequence independent of the active config and tags.

### 5. Sort and explain contract

`score` is first-class node data for priority surfaces.

- `survey` orders by `actionability → score desc → canonical-id asc`.
- `next` shows the actionable frontier. Wherever surviving seq precedence is silent,
  it orders by `score desc → canonical-id asc`; along surviving seq chains, structure
  wins. The implementation must not replay seq edges that cordage evicted to make the
  structural order acyclic.
- `explain` exposes the score breakdown: base, value dimension, risk dimension,
  recursive leverage, one-hop optionality, and total. The value line labels its
  source and, when projected, the bounds and evidence weight — e.g.
  `value: 6.2 (projected, bounds (3.2, 9.1), 9 judgements)` vs
  `value: 8.0 (authored)`.

No score or reverse consequence is authored to disk. Scores are derived in memory
from authored facets, config, and outbound relations.

Rejected alternatives:

- **Keep raw inbound count.** Simple but blind to value, estimate, and risk — the
  defect IMP-118 exists to fix.
- **One-hop consequence for all edge classes.** Safe, but misses deep blockers whose
  value appears beyond one dependent.
- **Recursive consequence for all relation overlays.** Treats cyclic-capable lineage
  and associative references as causal dependency chains; termination and semantics are
  wrong.
- **Use score in graph mint order.** Creates feedback: graph-derived data would affect
  the structural order of the graph that produces it.
- **Make seq a score clamp/weight now.** More complex and tie-prone; current policy is
  structural precedence first, weighted ordering only where structure is silent.

## Consequences

### Positive

- Priority surfaces rank by the value and risk of what an item unlocks, not by a raw
  edge count.
- Deep blockers become visible through recursive needs leverage.
- Score is explainable: large numbers decompose into base, leverage, and optionality.
- The mint/display split prevents scoring feedback loops while still making display
  order score-aware.
- Config and tag edits can deliberately retune ordering for a purpose without code
  changes, while durable coefficient domains keep the policy coherent.

### Negative

- Scores are floating-point values; implementation must enforce deterministic ordering
  and keep non-finite values away from sort keys and render output.
- Recursive path-sum leverage can grow sharply in wide reconvergent graphs. This is
  accepted semantics, but it can surprise operators until `explain` is consulted.
- `next` needs an explicit frontier sort over surviving seq constraints; plain cordage
  `order_key` is insufficient because level precedes the mint tiebreaker.
- Golden output churn is expected: `survey`, `next`, and `explain` change from inbound
  count to score columns/breakdowns.

### Neutral

- Numeric defaults are not governance. They may change as the corpus teaches better
  weights, without amending this ADR.
- Priority order is purpose-sensitive: changing coefficients or tags is expected to
  change `survey` / `next` ordering.
- Tag coefficients are part of the formula now, but tag storage can arrive later; until
  then, the tag term contributes its identity.
- The per-item priority override is the **pin** (REV-024): a governed,
  attributed, supersedable ledger row admitted only through the
  operator-gated `value pin` verb (interactive-TTY + worker-refused write
  class) — never a side effect of typing a number. Cost/maintainability
  dimensions remain future work (IDE-035 holds the trigger); the comparison
  ledger (RFC-019/020) is now the value-evidence history for absolute and
  relative judgements alike; score history as such remains future work.

## Verification

- Base-score tests cover value-only, risk-only, combined, absent facets, estimate
  identity, kind-weight defaults, and tag identity.
- Consequence tests prove direction and class semantics: needs leverage uses dependent
  edges recursively; reference optionality uses only the configured work/lineage label
  subset one hop; bookkeeping labels contribute zero.
- Recursive leverage tests cover a chain, a reconvergent diamond, and a diagnosed needs
  cycle with condensation and finite output.
- Sort tests prove: graph mint uses base only; `survey` uses score; `next` orders
  seq-incomparable actionable items by score while preserving surviving seq precedence
  and ignoring evicted seq edges.
- Determinism tests prove total ordering for equal scores and no NaN/∞ reaches mint,
  surface sorting, JSON, or human render.
- Explain tests assert the full `{base, value_dim, risk_dim, leverage, optionality,
  total}` breakdown so retuned rankings remain diagnosable.
- ADR-001 layering gate stays green: risk types live below command-tier consumers and
  priority config/scoring do not import command modules upward.
- ADR-004 is preserved: no authored reverse/consequence fields are added; consequence
  remains derived from outbound relations.
