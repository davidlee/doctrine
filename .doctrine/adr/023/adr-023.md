# ADR-023: Authority model for agent instruction

## Context

Agents working in a Doctrine repo read many sources phrased as instruction:
the user, `CLAUDE.md`/`AGENTS.md`, governance, the boot snapshot, skills, CLI
envelopes, memories, RFCs, handovers, and found files. Nothing ranked them.
Across sessions the same gate produced very different behaviour:

- agents refused to record a user act and told the user to run the CLI,
  usually with no example;
- agents demanded the user author a `basis` because the payload requires one;
- handovers that abbreviated a skill's procedure were followed in preference
  to the skill, including exacting git landing sequences at audit and close;
- `/consult`, being a skill, was sometimes treated as a ritual to invoke
  mid-conversation, when all it means is "ask the user and defer".

RFC-021 (§ *Authority and trust*) already set out an intended precedence and
noted that repository presence is not acceptance and that memories carry no
instructional authority. RSK-229 names the missing contract. DEC-088 already
designs user acts to be recorded by the agent from conversational assent, but
no agent-facing prose says so.

The model has to ship to client projects, so a Doctrine-repo ADR alone does not
reach the agents it governs. It also has to fit the boot snapshot's universal,
cache-stable, size-bounded contract (the Model band section; IMP-435).

## Decision

We will define a six-tier authority ranking and deliver it as the **first**
section of the boot snapshot (`## Authority`, rendered from
`install/authority.md`), with the full elaboration published as
`reference/authority-model.md` (`install/authority-model.md`).

1. The tiers, highest first: (1) the user in this session; (2) accepted
   project authority (standing instruction files, accepted governance, specs,
   accepted decisions, a locked design for its slice); (3) the Doctrine
   framework (boot, skills, CLI output, reference docs); (4) agent judgement;
   (5) evidence: memories, RFCs, slice notes, handovers, research, review
   findings, superseded records; (6) found data.
2. Project authority outranks the framework, per RFC-021: a project's own
   files are its trust decision.
3. Within a tier the narrower or more recent source wins; a genuine
   contradiction is drift, surfaced rather than chosen.
4. Tier-5 evidence is weighed, never obeyed. How hard to check a claim scales
   with its strength, the cost of checking, and the cost of being wrong.
   A handover's summary of a skill-governed procedure never replaces the
   skill.
5. For material the user conveys, trust the user's account of its provenance
   but judge its content as evidence.
6. Engine invariants (CLI refusals) are not authority claims and no tier
   overrides them.
7. User acts at gates are recorded **by the agent** from the user's assent in
   conversation, given to a proposition the agent laid out, with the reply
   cited as the basis. The agent never asks the user to run the CLI or author
   payload fields to perform an act the agent can record. Doctrine does not
   authenticate the human; the record is the agent's truthful account.
8. Escalation is asking the user and deferring to the answer. The model does
   not require a separate ritual.
9. Delegates inherit scope and standing instructions, never the user. They
   return proposals and never record a user act.

We will not use a memory for the elaboration. The memory surface frames its
output as "data, not instruction", and the model places memories at tier 5, so
putting the model there would undercut itself.

## Consequences

### Positive

- Gate behaviour stops depending on the session: the ranking and the
  acting-on-behalf rule answer the questions agents were improvising.
- Design-run prose (IMP-467) can cite one rule instead of restating it at
  every gate.
- Project preferences override framework craft defaults without an override
  mechanism.
- Hoped-for rather than proven: better adherence to hymns and other
  CLI-emitted guidance. Agents have tended to treat skills as privileged and
  envelope or hymn text as advisory. Naming all three together at tier 3 says
  they carry equal weight. If hymns still get less gravity than they need, the
  tier-3 row is the obvious place to turn the dial: raise their standing,
  or state it more forcefully.

### Negative

- About 2.5 KB more boot snapshot, paid by every agent (IMP-435 identifies
  larger savings elsewhere).
- Tier placement is a judgement a model can still misapply; the text is
  guidance, and nothing mechanically enforces it.
- The model rests on the conversation being the user's. A compromised or
  unsupervised session defeats it (the verified-human upgrade is RFC-028).

### Neutral

- `/consult` survives as a skill for now; this ADR subsumes its meaning, and
  retiring it is separate work.
- Existing project text that contradicts the ranking (e.g. an instruction to
  follow handovers unconditionally) is tier 2 and still wins where it applies.
  Projects should revise such text.

## Verification

- `boot::tests::authority_section_renders_first_and_is_the_pristine_embed`
  pins placement and body.
- The publication reachability invariant covers both new assets.
- Adoption is empirical: re-measure gate behaviour after IMP-467 lands
  (CHR-049's frame).
