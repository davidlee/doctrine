# ADR-011: Harness-agnostic orchestrator spawn interface and per-harness capability altitude

> **AMENDED — FALSIFIED (SL-254, 2026-08-14).** This ADR's second theme is dead.
> SL-254 collapsed dispatch from **two arms** — an in-session "claude arm" using
> Claude's `Agent` tool with `isolation: worktree`, and a subprocess arm for
> codex/pi — onto **one confined subprocess arm**: every harness, claude
> included, is spawned by `scripts/spawn-confined.sh <harness>` and wrapped in a
> kernel-level `bwrap` (Linux) / `sandbox-exec` (macOS) jail. There is no
> per-harness capability altitude left to state: no altitude table, no in-session
> `Agent` spawn backend, no disk marker, no `SubagentStart` stamp, no
> base-by-placement, and no "degraded harness" rung (`DEC-208` — on Linux a missing
> `bwrap` is a **named refusal**, fail closed; on macOS there is no
> `sandbox-exec` presence probe, so the equivalent failure is closed but
> **unnamed**). Worker identity is `DOCTRINE_WORKER == "1"` and nothing else
> (`DEC-207`) — a value compare, so `DOCTRINE_WORKER=0` is set but is not worker
> mode.
>
> The title's second half — "per-harness capability altitude" — is therefore
> **false**, and the title is **deliberately left unchanged**: this repo has no
> precedent for retitling an ADR on amendment, so the falsity is recorded here
> instead. Likewise this ADR is **amended in place, not superseded** (owner
> ruling, 2026-08-14) — every historical body below is retained as the record of
> what was decided, and no longer describes the shipped posture.
>
> **This document's own Verification section is now self-contradicting.** Its
> second criterion reads *"the altitude table shows codex/pi vs claude on each
> axis; no harness-specific command (`claude -p`) appears as a required
> element."* Shipped code contradicts both halves: there is no altitude table,
> and `scripts/spawn-confined.sh:220` execs exactly `claude -p --output-format
> stream-json` on the sole spawn path — a harness-specific command **is** now a
> required element. See the Verification amendment below.

## Context

> **AMENDED — FALSIFIED (SL-254, 2026-08-14).** The keystone stated here —
> *"identity rides disk — the one medium every harness has — not a process env
> seam, which not every harness has"* — is **inverted**. Identity is now the
> `DOCTRINE_WORKER` env var and nothing else (`DEC-207`); the disk marker at
> `<root>/.doctrine/state/dispatch/worker` is deleted, and
> `src/worktree/marker.rs` is a ~129-line env-only module whose own header
> records that *"the disk marker this module was named for is gone."* Identity is
> a property of the **process**, not of a tree: it is set by the same confinement
> argv that establishes the write floor, and it dies with the process.
>
> The two premises this paragraph rested on are also gone. (a) *"claude's `Agent`
> tool has no env channel … for claude the only viable backend is the in-session
> `Agent` tool"* — claude is not spawned in-session at all any more; it is a
> confined subprocess like every other harness, and so has an env channel by
> construction. (b) *"`claude -p` is Anthropic-API-billed (not subscription) and
> harness-specific — so neither an env seam nor a subprocess spawn can be a
> *required* element of a harness-agnostic framework"* — the shipped path execs
> `claude -p` as a required element (`scripts/spawn-confined.sh:220`) and
> deliberately withholds `ANTHROPIC_API_KEY` / `--bare` precisely to keep
> subscription billing (`DEC-210`). Harness-specific spawn commands are now the
> design, not a forbidden concession.
>
> What survives: the opening thesis — mechanism in prose is the design smell; a
> mechanism moved into the binary is identical under every harness by
> construction — is **unfalsified and was strengthened** by SL-254. The "three
> small read verbs" inventory is a June-2026 snapshot, not a claim about today.
> What does not survive is the framing sentence *"This ADR fixes the **contract**
> every harness honours and the **altitude** each can reach"*: there is one
> altitude now, it is uniform, and it is mandatory.

**Mechanism in prose is the design smell** (SL-056 thesis, surfaced by SL-055's
holistic skills review). The worktree/dispatch CLI today owns three small read
verbs (`provision`, `check-allowlist`, `branch-point-check`); everything else —
the fork-creation ladder, the import funnel, worker-mode enforcement, build
isolation, GC — lives as **prose asking an LLM to replay git command sequences.**
That prose is token-heavy (the two fattest skills), **untestable** (no golden pins
a prose ritual), **fail-open** (a skipped step refuses nothing), and
**harness-coupled by accident** (written against Claude's `Agent` affordances). A
CLI verb is identical under claude/codex/pi by construction — each mechanism moved
into the binary makes skills shorter **and** more agnostic in the same move.

The trust-bearing core is **who controls the worker's worktree and identity**. The
keystone is **the orchestrator owning fork-or-mark + provision + per-worktree env
emission, and stamping a disk marker** into the worker's worktree before the worker
runs: **identity rides disk — the one medium every harness has — not a process env
seam, which not every harness has** ([[mem.pattern.dispatch.spawn-backend-harness-agnostic-no-free-env-seam]]).
claude's `Agent` tool has no env channel, and `claude -p` is Anthropic-API-billed
(not subscription) and harness-specific — so neither an env seam nor a subprocess
spawn can be a *required* element of a harness-agnostic framework (SL-056 Charge
XIII). For claude the only viable backend is the in-session `Agent` tool, which
exposes no env seam and no exec wrapper.

This ADR fixes the **contract** every harness honours and the **altitude** each can
reach. It **references ADR-006 and does not amend it** — the ADR-006 D2a/D5/D9
amendments are a separate, spike-gated step (SL-056 G2/PHASE-03), authored only
after the O3 spike (PHASE-02) validates the claude path.

## Decision

> **AMENDED — FALSIFIED (SL-254, 2026-08-14).** The mechanism/concession line
> drawn here — the binary side is the contract, and *"how the worker is spawned
> (harness-shaped → prose, selected by the `/dispatch-*` router)"* is a
> per-harness concession — no longer exists. Spawn is neither prose nor
> per-harness: `scripts/spawn-confined.sh <harness>` is the sole spawn path, and
> the two router skills it was selected between (`dispatch-agent/SKILL.md`,
> `dispatch-subprocess/SKILL.md`) were merged into the single
> `plugins/doctrine/skills/dispatch-spawn/SKILL.md` (SL-254 PHASE-07). There is
> no concession side left to route to, and no `/dispatch-*` router to route with.

The mechanism/concession line falls between **what the binary does** (create-or-mark
+ provision + per-worktree env *contract* emission — harness-identical) and **how
the worker is spawned** (harness-shaped → prose, selected by the `/dispatch-*`
router). The binary side is the contract; the spawn side is a per-harness concession.

### D1 — Worker identity is an orchestrator-stamped disk marker (agnostic floor)

> **AMENDED — FALSIFIED (SL-254, 2026-08-14).** The heading is false: worker
> identity is **not** an orchestrator-stamped disk marker, and there is no
> "agnostic floor" beneath it. Per `DEC-207`, identity is the `DOCTRINE_WORKER`
> environment variable **and nothing else** — set by the confinement argv: on Linux
> `--setenv DOCTRINE_WORKER 1` in `scripts/spawn-confined.sh:183`'s inline bwrap
> array, on macOS the trailing `env DOCTRINE_WORKER=1` token
> `jail.rs::sandbox_exec_argv` appends. `jail.rs::bwrap_argv` sets **no** env at all
> (corrected SL-254 — an earlier draft of this amendment cited it as a setter); the
> Linux env leg lives in the shell script, not in the Rust argv builder. Identity
> dies with the process. The marker file at
> `<root>/.doctrine/state/dispatch/worker`, `marker --stamp-subagent`,
> `marker --clear`, `status --assert`'s stale exit, and the whole `Cause` truth
> table are all retired.
>
> The guard pseudocode below is therefore superseded. The shipped guard
> (`src/commands/guard.rs::worker_guard`) has no marker leg and no root
> resolution:
>
> ```
> worker_mode := env DOCTRINE_WORKER == "1"     // the whole rule — no marker, no root
>                                               // a VALUE compare: `=0` is set, not worker
> guard: if worker_mode: refuse(verb)           // Write- and Orchestrator-classed verbs, named
> ```
>
> `marker::describe_mode(env_set: bool)` is correspondingly a **two-row** truth
> table (SL-056's was eight rows over three inputs). The demotion of
> `DOCTRINE_WORKER` to "a codex/pi optimisation, not the identity" is exactly
> reversed. The **worker-on-main** hazard the env leg was demoted to catching is
> no longer a special case: mode still decides rather than location (ADR-006
> D6a), but the sole signal is the env var, and it is present exactly when a
> confined worker process is running.

Worker-mode is a property of the **worker**, signalled by a **disk marker the
trusted orchestrator stamps before the worker runs** — presence-only, no contents,
at the withheld-tier path `<root>/.doctrine/state/dispatch/worker`. The guard is:

```
worker_mode(root) := (is_linked_worktree(root) && marker_present(root))  // PRIMARY, agnostic
                     OR env DOCTRINE_WORKER set                          // codex/pi worker-on-main catch
guard (in run(), before a write-classed OR Orchestrator/Hook-mint Command):
    if worker_mode(root): refuse(verb)   // names the verb
```

The marker is **primary and harness-agnostic**; `DOCTRINE_WORKER` is a **codex/pi
optimisation, not the identity** — its one job is to catch the **worker-on-main**
hazard (a harness that drops the worker on the coordination root, where no marker
exists). Solo `/execute` sets neither signal → writes freely: **mode, not location,
decides** (ADR-006 D6a).

### D2 — The orchestrator owns the trusted act; the worker writes source only

> **AMENDED — PARTLY FALSIFIED (SL-254, 2026-08-14).** The first paragraph
> **holds, and is stronger**: the orchestrator remains the sole doctrine-mediated
> writer, and the worker returns a source delta and never writes doctrine state.
> It is stronger because the worker now **cannot commit at all** — `worker_commit`,
> the claude arm's gated worker self-commit MCP tool, is deleted (`DEC-204`). The
> worker hands back an **uncommitted working tree** and the orchestrator imports
> the working-tree diff; forks stay **unbound** (no `DispatchRecord` is written,
> and the funnel row is named by the orchestrator's explicit `PHASE-NN`). One
> term of the stated agnostic core is wrong: it is fork + provision +
> **confinement**, not "+ marker" — the marker is gone (`DEC-207`; see D1).
>
> The second paragraph — *"per-worktree env: emission is a contract, delivery is
> subprocess-only"* — is **falsified as a split**. There is only a subprocess path
> now, so emission and delivery land in the same place on every harness; the
> claude-cannot-consume-it exception (IDE-004) has no referent, because there is
> no in-session claude path to except. The generalisable-contract /
> project-local-consumer distinction (`CARGO_TARGET_DIR`, ADR-008 D-B1, never a
> framework primitive) is unaffected.
>
> **One correction of record**, since this section defines what the worker may
> write: the import belt (`src/worktree/import.rs::classify_import`) enforces the two
> hard-coded prefix floors `.doctrine/**` and `.claude/**`, **plus** a third
> rejection leg — the `--slice`-scoped `undeclared-scope` check
> (`Refusal::UndeclaredScope`, `import.rs:136-152`). It never
> enforced `DispatchConfig::worker_forbidden_writes` — `worker_commit` was that
> config key's only production reader, so with it deleted the configurable tail
> (`.agents/**`, `install/agents/**`, `flake.nix`) now enforces **nothing**. That
> gap is carried to `SL-255` (`IDE-051`: enforce it via read-only binds at spawn
> time, not a post-import belt).

The orchestrator is the **sole doctrine-mediated writer**. The **agnostic core** —
the trusted act it owns on **every** harness — is **create-or-mark + provision
(ADR-006 D9 allowlist, withheld tier excluded) + marker**. The worker returns a
source delta; it never writes doctrine state.

**Per-worktree env: emission is a contract, delivery is subprocess-only.** The
binary may *compute and emit* a per-worktree env contract (`KEY=value` on stdout) —
that emission is harness-identical. **Delivery to the worker is not:** a subprocess
harness (codex/pi) injects it into the worker's environment (`env -C`/bwrap), while
**claude's `Agent` path has no worker env channel and cannot consume it** today
(IDE-004). So env emission is part of the *contract* but not part of the
*everywhere-enforced* core. The contract is **generalisable**; the **project**
declares its own consumers — doctrine-the-repo's
`CARGO_TARGET_DIR=<jail-root>/wt/<branch>` (ADR-008 D-B1) is one project-local
consumer, **never a framework primitive**.

### D3 — Per-harness capability / altitude table

> dead**, and so is the section it heads. There is no per-harness capability
> altitude: one confined subprocess arm serves every harness, so there are no
> columns left to compare. Row by row, for the record:
>
> - **Spawn backend** — `scripts/spawn-confined.sh <harness>` for all; for claude
>   it execs `claude -p --output-format stream-json` (`:220`), which **directly
>   contradicts** this section's preamble that *"no harness-specific command
>   (`claude -p`) is a required element"*. The in-session `Agent` tool with
>   `isolation: worktree` is no longer a dispatch backend at all.
> - **Worker identity** — `DOCTRINE_WORKER` only, on every harness (`DEC-207`).
>   No marker, on either column.
> - **Marker writer** — no marker and no writer. `src/worktree/subagent.rs` (the
>   `SubagentStart`/`SubagentStop` stamping and worker nomination) is deleted
>   whole, as is `src/worktree/pretooluse.rs` (the `PreToolUse` hook wall);

>   `WorktreeCreate` `create-fork` note is moot.
> - **Base pinning** — explicit fork with a named base on every harness.
>   Base-by-placement (`worktree.baseRef='head'`, orchestrator cwd == coord tree)
>   is gone with the in-session arm.
> - **Per-wt build isolation** — no claude exception; every worker is a
>   subprocess in its own fork.
> - **OS confinement** — **mandatory and fail-closed on every harness**: bwrap
>   (Linux) / `sandbox-exec` (macOS) wraps every worker exec, and a missing `bwrap`
>   is a named refusal (`jail.rs::REASON_NO_BWRAP`,
>   `scripts/spawn-confined.sh:62-64`) — Linux only; macOS runs no backend probe and
>   fails unnamed at exec. Not "spike/D6-contingent", and never "none" for claude.
>   **"Uniform" is true across harnesses, not across platforms** (corrected SL-254):
>   the Linux and Darwin argv differ on network (Darwin's profile emits
>   `(deny network*)`; the Linux inline bwrap array carries no `--unshare-net`, so a
>   Linux worker is fully networked) and on process lifetime (`--die-with-parent` has
>   no Seatbelt analog). The writable set is also **not** the fork worktree alone —
>   the harness config dir (`~/.claude` / `~/.pi`) is rw-bound inside the jail, a
>   deliberate and security-relevant carve-out (`DEC-210`).
> - **Worker-on-main catch** — not a per-harness gap: the env var is set by the
>   same argv that confines the worker.
> - **Concurrency** — unchanged in substance (file-disjoint execution; one landing
>   per base), but it is no longer a per-harness row.
> - **Fail-closed altitude** — one altitude, uniform and mandatory. The
>   `SubagentStart`-stamp row, its "blocking ⇒ stamp-before-worker" reasoning and
>   its "not fail-closable" caveat all describe deleted machinery.

The contract is uniform; the reachable altitude is not. **No harness-specific
command (`claude -p`) is a required element** — it is at most a codex/pi
enhancement layer.

| Axis | **codex / pi** (`/dispatch-subprocess`) | **claude** (`/dispatch-agent`) |
|---|---|---|
| Spawn backend | subprocess (`codex exec` / pi) binding worker cwd via `env -C "$D"` / bwrap `--chdir` | in-session **`Agent` tool**, `isolation: worktree` — **first-class, not a degraded rung** |

### D4 — codex/pi enhancements ride the subprocess seam; the marker floor does not

> **AMENDED — FALSIFIED (SL-254, 2026-08-14).** The heading's premise is gone
> twice over: there is no marker floor, and there is no codex/pi-only seam. All
> three "codex/pi-only until a free claude env backend lands" enhancements are
> now **uniform**, and two are not enhancements at all. (a) `DOCTRINE_WORKER` is
> **the identity**, not an optimisation of a marker (`DEC-207`). (b) Per-worktree
> env *delivery* reaches every worker, because every worker is a subprocess.
> (c) **Kernel confinement is not an enhancement tier** — bwrap (Linux) /
> `sandbox-exec` (macOS) wraps every worker exec: on Linux `--ro-bind / /` makes the
> whole filesystem read-only, on macOS an SBPL `(deny file-write*)` floor fences
> writes only (there is no `--ro-bind` on that path), and in both cases the writable
> set is the fork's worktree **plus the harness config dir**, not the worktree alone.
> Its absence **refuses the spawn** rather than degrading — by name on Linux, unnamed
> on macOS for want of a backend probe. The "degraded
> harness" / reduced-enforcement-altitude rung is abolished (`DEC-208`): there is
> no unconfined fallback.
>
> **Base pinning is uniform too**, contradicting this section's second paragraph:
> claude does not receive "provision + marker through the matcher-scoped
> `SubagentStart` stamp … but NOT explicit base pinning" — that hook and that
> marker do not exist, and the subprocess arm forks explicitly for every harness.
> The customer split that closes this section ("the agnostic core has live
> customers on all three staged jail harnesses; base-pinned fork and the three
> subprocess enhancements have customers on codex/pi only") no longer names a
> real division — every customer is on the same path.

Three enhancements are **codex/pi-only until a free claude env backend lands**
(IDE-004 channels — optimisation tier, never required): (a) env-arm
`DOCTRINE_WORKER` (an optimisation of the marker, not the identity); (b) per-worktree
env *delivery* (the generalisable emission contract of D2 reaching the worker, of
which `CARGO_TARGET_DIR` is a project-local consumer); (c) nested bwrap (ADR-008
D-B3).

**Base pinning is not uniform.** Base-pinned `fork --base <B>` is delivered for
subprocess harnesses (codex/pi). **Claude receives provision + marker through the
matcher-scoped `SubagentStart` stamp hook (atop its own default creation), but NOT
explicit base pinning** — Claude chooses the base opaquely, and its base-pinning
residual is D5. (The `create-fork` create+provision+stamp-in-one-act path is deferred —
SL-056 PHASE-02; D6.) The agnostic core
(create-or-mark + provision + marker — D2) has live customers on all three staged
jail harnesses (`jailed-pi`, `jailed-claude`, `jailed-codex`); base-pinned fork and
the three subprocess enhancements have customers on codex/pi only.

### D5 — claude base-pinning is a confessed residual, not parity (charge-2) — FALSIFIED (SL-064 §8)

> **AMENDED — FALSIFIED (SL-064 §8, 2026-06-14).** This cell's premise — "the base
> is **opaque and not orchestrator-controlled**" — is **wrong**, and a controlled
> marker-commit test disproved it (DD-15). Under `worktree.baseRef='head'` (the
> per-operator install, §8.3) the Claude isolated worker forks the **spawning
> orchestrator session's local HEAD** — so the base **is** orchestrator-controlled
> **by placement** (orchestrator cwd == the coordination tree, HEAD == B), not by a
> ref-redirect. The "clean-applying, semantically-wrong import" worst case below is
> **CLOSED** by the post-spawn `verify-worker` verb (`merge-base --is-ancestor B
> HEAD`, fail-loud, pre-import; SL-064 §8.4) — the IMP-043 content-base assertion the
> original text deferred is now delivered. The historical analysis below is retained
> for the record; it no longer describes the v1 posture.

> **AMENDED — FALSIFIED (SL-254, 2026-08-14).** Both the original body and the
> SL-064 §8 amendment above describe a world containing an in-session Claude
> worker; it no longer exists. There is no `worktree.baseRef='head'`, no
> base-by-placement (orchestrator cwd == coord tree, HEAD == B), and no
> Claude-chosen opaque base: the sole subprocess arm forks explicitly with a
> named base on **every** harness. Charge-2's residual, the M1 "clean-applying,
> semantically-wrong import" worst case, and the deferred IMP-043 content-base
> assertion all dissolve at the source rather than being caught (or missed)
> downstream.
>
> The failure analysis below is stale in a second way: it reasons about *"the
> worker's distilled commit"*, its parent `S^ != B`, and `import` refusing
> **`multi-commit`**. **The worker no longer commits** — `worker_commit` is
> deleted (`DEC-204`) and the worker hands back an uncommitted working tree that
> the orchestrator imports as a diff, so there is no worker commit to carry a
> parent. Forks stay **unbound**: no `DispatchRecord` is written, and the funnel
> row is named by the orchestrator's explicit `PHASE-NN`. The historical analysis
> is retained for the record; it describes no shipped mechanism.

**Sharper under SubagentStart-stamp (SL-056 PHASE-02/03):** Claude performs the
worktree creation and **chooses the base itself** — no orchestrator-supplied base
reaches any hook, and the spike observed the default-created worktree HEAD was **not**
the orchestrator's HEAD. So the base is **opaque and not orchestrator-controlled** —
weaker than the original "forks from session HEAD" assumption. This ADR does **not**
claim hook-time base parity with codex/pi's explicit `fork --base <B>`.

A wrong base is **usually** caught late: if the worker's distilled commit has a parent
`S^ != B`, `import` refuses **`multi-commit`** (SL-056 §7a — *not* `head-moved`, which
is the orthogonal `HEAD != B` orchestrator-side check), and the worker re-dispatches —
cost a **wasted worker run**. **But the catch is not total (M1 residual, accepted for
v1):** a delta that *presents* `S^ == B` (parent shown as `B`) while its tree was
developed against an opaque `B'` passes `multi-commit`, passes the belt, and can pass
`git apply --3way` **cleanly but semantically wrongly** (textual non-overlap ≠ semantic
correctness). So the worst case is a **clean-applying, semantically-wrong import**, not
always a bounded refusal — a confessed residual, not a closed case. An import-time
content-base assertion that would close it is **deferred to IMP-043** (owner-accepted
for v1); no hook-time `base-moved` pre-refusal is possible (no hook sees a base).

### D6 — claude fail-closed altitude (φ) — RESOLVED to O3-red (SL-056 PHASE-02/03)

> path and base — base control was never the blocker. The **real** blocker is the

> (global fire) ⇒ the σ blast-radius of D7. The achieved v1 altitude is
> `worktree.baseRef='head'` (base==B by placement, §8.3) **+** the matcher-scoped
> `SubagentStart` stamp **+** the post-spawn `verify-worker` belt (§8.4) — still **not
> pre-worker fail-closable** (the same accepted residual class as the body). The
> deferred `WorktreeCreate` pre-worker fail-closed arm is **IMP-072**, now gated
> *only* on a demonstrated need for true pre-worker fail-closability (arbitrary-B
> control is already solved by placement, so it is no longer a justification).

> `src/worktree/subagent.rs` (`SubagentStart`/`SubagentStop` stamping and worker
> nomination) and `src/worktree/pretooluse.rs` (the `PreToolUse` hook wall) are

> The containment argument is **replaced, not re-tuned**. Identity is set by the
> same argv that confines the worker, so an unconfined — and therefore
> unidentified — worker cannot be spawned at all: if `bwrap` is missing the spawn
> is refused **by name** (`jail.rs::REASON_NO_BWRAP`), fail closed, with no
> unconfined fallback and no reduced-enforcement rung (`DEC-208`). The claim that
> *"bwrap is codex/pi-only"* is false — confinement is uniform and mandatory. The
> residual this cell named as *silence* (an unstamped worker being
> signal-identical to a legit solo writer) does not arise: there is no unstamped
> state to be silent about.
>
> What remains true and load-bearing: the dispatch funnel `import` belt rejects
> `.doctrine/` and `.claude/` writes (report + halt), and the jail has no push
> access, so the worst case is still bounded at lost unpushed local work. Note
> the belt's reach is **exactly** those two hard-coded prefix floors plus the
> `--slice`-scoped `undeclared-scope` leg, and no more — see the D2 amendment on
> `worker_forbidden_writes`.

**The O3 spike came back RED and PHASE-03-A settled the SubagentStart altitude; this
cell is now asserted, not proposed.** The deployed Claude Code `WorktreeCreate` payload
carries no `agent_type`/`worktree_path`/base, so the fail-closed create-replacing arm
is **not achievable** (it can neither classify, target, nor base-pin a worker); it is
**deferred** until the payload grows those fields (or an IDE-004 channel lands). The
achievable altitude is **SubagentStart-stamp**:

- A **matcher-scoped, sync-blocking** `SubagentStart` hook provisions + stamps the
  marker into the worker's `cwd`. Because the hook blocks the worker until it exits,
  **the marker is mechanically present before the worker's first command — on hook
  success.** This is **stronger than the original O3-red framing on the race axis**:
  there is *no* worker-execution race (the "created-but-unstamped window" is not a
  timing race against the worker).
- **But SubagentStart is a read-only event** (docs + PHASE-03-A: no exit status, incl.
  `exit 2`, can abort the subagent). So the residual fail-open is a **hook-failure
  case** (the stamp errors → the worker runs unstamped), **un-gateable by the hook**.
  This is **not fail-closable**.

**The fail-open is contained by the funnel + the jail, not by fail-closing the write**
(re-amended SL-056 PHASE-05, owner-locked VH; supersedes the G2 B2/B3 fail-closed
framing — see ADR-006 D2a). A stamp-failed worker runs `marker_present=false` and is
therefore **not** refused at the CLI write seam: refusing it would contradict ADR-006
D6a's solo-in-worktree direct-writer, and re-weighed against the actual risk —
`P(hook failure) ≈ 0` (the hook blocks; a miss needs a crash) **×** *jail-bounded* harm
(no push ⇒ worst case is lost local work) — the fail-closed floor bought negligible
security over the funnel. Its blast radius is bounded instead by: the **dispatch funnel
`import` belt** (`.doctrine/`+`.claude/`-rejection, SL-056 §7 — an unstamped worker
writing into its own fork is caught at import, report+halt); the **pre-distilled
prompt**; and the **bubblewrap jail with no push access** (ADR-008), which caps the
worst case at *lost unpushed progress*. The residual under this posture is not *harm*
but *silence* — an unstamped worker is signal-identical to a legit solo writer, so a
failing hook could quietly become the status quo; this is closed by an **orchestrator
post-spawn marker check that aborts the unstamped fork** (IMP-052), enforcing at the one
layer that **can** abort where this read-only hook cannot. The sole marker-minting verb
(`marker --stamp-subagent`) is exempt **by verb identity** (its `cwd` *is* a linked
worktree). With this posture, claude worker-sole-writer is **funnel-fenced +
jail-bounded + prompt-enforced + spawn-time-observable** — still **not malice-proof**
against an OS-level escape (no env-lock; bwrap is codex/pi-only) until IDE-004 /
userns-bwrap (ADR-008 D-B3; macOS analog IMP-045).

**Matcher caveat (M2):** the literal `dispatch-worker` matcher path is **doc-supported
but not yet end-to-end probed** (the agent-def registry needs a fresh session; PHASE-03-A
proved the mechanism with `general-purpose`). A matcher↔`DISPATCH_WORKER_AGENT_TYPE`
drift makes the hook **not fire at all** ⇒ unstamped worker ⇒ caught by the funnel
`import` belt + the IMP-052 orchestrator post-spawn marker abort above (not free). A
fresh-session matcher probe is owed (tracked IMP).

### D7 — σ blast-radius — WITHDRAWN (SL-056 PHASE-02/03; no longer a residual)

> **AMENDED — confirmed for v1 (SL-064 §8, 2026-06-14).** The withdrawal **holds for
> v1**: no `WorktreeCreate` hook is installed, so there is no global create-intermediation
> and no blast radius. The amended D6 makes σ explicit as the **gate** on the deferred
> `WorktreeCreate` pre-worker fail-closed arm (IMP-072): reviving create-replacement
> would re-introduce global creation-replace, a benign pass-through, and a
> discriminator race — i.e. it would **re-open** σ. So σ is withdrawn as a *current*
> residual but stands as the *named cost* of the deferred follow-up.

> **AMENDED — still withdrawn, but for a new reason (SL-254, 2026-08-14).** σ
> remains withdrawn, and neither prior reason is the operative one: not the
> original ("the `SubagentStart`-stamp path does not intermediate creation"), nor
> SL-064 §8's ("no `WorktreeCreate` hook is installed for v1"). **There is no
> in-session subagent creation on the dispatch path at all.** The `Agent`-tool arm
> is gone, and with it every hook that could have intermediated worktree creation
> — `src/worktree/subagent.rs` and `src/worktree/pretooluse.rs` are deleted whole.
> A create-replacing `WorktreeCreate` arm has nothing left to revive, so σ is not
> even the named cost of a deferred follow-up; the follow-up is unreachable from
> the shipped design. The "benign isolated subagents revert to Claude's bare
> default creation" disposition below is likewise moot — `/dispatch` no longer
> spawns subagents in-session at all.

σ was an artifact of the create-replacing `WorktreeCreate` hook, which would have
intermediated creation for *every* worktree and so needed a shared create+provision
core and a benign else-branch (the blast radius). **The SubagentStart-stamp path does
not intermediate creation at all** — Claude creates every worktree by default; the hook
only fires per-subagent and stamps, and its **matcher scopes the stamp to
`dispatch-worker`**. There is **no else-branch and no shared creation core**, so the
blast radius does not arise. The "benign isolated subagents gain `.worktreeinclude`
provisioning" upside was a *side-effect* of creation-replacement, **never a
requirement** — the SL-056 PHASE-03 review confirmed **no skill or verb depends on a
benign isolation:worktree subagent being provisioned** (`/worktree` provisions its own
forks; `/dispatch` forbids `Agent isolation:worktree`). Benign isolated subagents now
revert to Claude's bare default creation (unprovisioned) — **a deliberate scope cut with
zero dependents, not a functional loss.** This confession is withdrawn; the matcher
question and the delete-vs-keep-else-branch disposition both dissolve.

## Verification

> **AMENDED — FALSIFIED (SL-254, 2026-08-14).** **Every criterion below now fails
> against shipped code, and the second fails by direct contradiction.**
>
> - **VA 1** (the contract reads as create-or-mark + provision + marker, with env
>   *delivery*, base-pinning, `DOCTRINE_WORKER` and bwrap stated as codex/pi-only
>   and never the identity): false in every term. There is no marker;
>   `DOCTRINE_WORKER` **is** the identity (`DEC-207`); and all four "codex/pi-only"

> - **VA 2** (*"the altitude table shows codex/pi vs claude on each axis; no
>   harness-specific command (`claude -p`) appears as a required element"*):
>   **this ADR now fails its own criterion, on both halves.** There is no altitude
>   table — D3 is dead — and `scripts/spawn-confined.sh:220` execs `claude -p
>   --output-format stream-json` on the *sole* spawn path, so a harness-specific
>   command **is** a required element. This is not a drafting slip to be reworded:
>   the criterion encoded this ADR's core premise — harness-agnosticism achieved
>   by abstaining from harness-specific commands — which SL-254 deliberately
>   abandoned, trading that abstinence for one spawn path and uniform kernel-level
>   confinement. The criterion is recorded as **falsified**, not repaired.

>   leaned on.

>   the conclusion holds, the reason does not — see the D7 amendment.
> - **VA 5** (the charge-2 base-pinning residual, sharper under Claude-chosen
>   opaque bases): dissolved — every harness forks explicitly with a named base.
>
> **No replacement criteria are asserted here, deliberately.** Authoring a fresh
> verification basis for the collapsed arm would be taking a new decision, which
