# ADR-008: Project-local jail build isolation and worker confinement for parallel dispatch

> **AMENDED — BROADLY FALSIFIED (SL-254, 2026-08-14).** SL-254 collapsed dispatch
> from **two arms** — an in-session "claude arm" driving Claude's `Agent` tool with
> `isolation: worktree`, and a subprocess arm for codex/pi — onto **one subprocess
> arm**: every harness, claude included, is spawned by
> `scripts/spawn-confined.sh <harness>` and wrapped in a kernel-level jail (bwrap on
> Linux, `sandbox-exec` on macOS). Three consequences run through this whole
> document and are not repeated at every mention.
> **(1) D-B3's central claim inverts.** Per-worker nested confinement is not a
> codex/pi-only enhancement that the claude arm cannot have; it is **uniform,
> mandatory and fail-closed on every harness** — on **Linux** a missing `bwrap` is a
> *named* refusal to spawn (`scripts/spawn-confined.sh:62-64`,
> `src/worktree/jail.rs::REASON_NO_BWRAP`), with no unconfined fallback and no
> reduced-enforcement rung (`DEC-208`). **On macOS the refusal is not named**: there
> is no `sandbox-exec` presence probe anywhere (`have_bwrap` is
> `#[cfg(not(target_os = "macos"))]` with no Darwin sibling;
> `spawn-confined.sh:61` skips the probe on Darwin), so a mac lacking the backend
> gets a successful prefix write followed by an unnamed exec failure. Fail-closed on
> both; *named* only on Linux. What this ADR called an enhancement is now
> the floor.
> **(2) The disk marker is gone.** Worker identity is the `DOCTRINE_WORKER`
> environment variable and nothing else (`DEC-207`) — a property of the *process*,
> set by the same confinement argv that establishes the write floor, dying with the
> process. Every "marker" and "marker-primary" phrase below names a deleted object.
> **(3) D-B6 is retired whole.** The nominated-unjailed orchestrator was authored
> into this ADR by **REV-021** out of `SL-206`; SL-254 retires its mechanism.
> `src/worktree/subagent.rs` and `src/worktree/pretooluse.rs` were deleted entire,
> and **Mode B** — the confined in-session orchestrator D-B6 named as its reversible
> escape hatch — was retired with them (`DEC-217`).
> The **title still holds**: this ADR is still about project-local jail build
> isolation and worker confinement, and D-B1/D-B2/D-B4 survive. Historical bodies
> are retained throughout for the record; per-region amendments mark what each one
> now gets wrong.

## Context

> **AMENDED — FALSIFIED (SL-254, 2026-08-14).** Two premises in this Context are now
> false.
> **(a)** The discharge of ADR-006 D2b is no longer conditional. Read below, it is
> conditional on *a subprocess existing to wrap* ("a generic harness cannot confine a
> worker to its worktree"); doctrine no longer uses any harness's own
> worktree-creating agent tool, so there is no harness for which the confinement is
> unavailable, and the discharge is unconditional.
> **(b)** The worker-sole-writer guarantee does **not** ride "the disk marker + the
> `import` `.doctrine/`-rejection belt". The disk marker is deleted (`DEC-207`); the
> guarantee now rides the kernel jail — `--ro-bind / /` on Linux (an SBPL
> `(deny file-write*)` floor on macOS, where `--ro-bind` does not exist), whose
> writable set is the fork's worktree **plus the harness config dir**
> (`~/.claude` / `~/.pi`, bound rw at `spawn-confined.sh:179` / granted as `RW0` at
> `:159`), plus a private `/tmp` and `/dev`. It is **not** the fork worktree alone,
> and the carve-out is security-relevant: `~/.claude` holds `settings.json`, hooks
> and agent definitions, so a confined claude worker can write the orchestrator's
> own harness configuration — a deliberate grant (`DEC-210`: claude needs it for the
> subscription credential), with the narrowed mount set a known, untaken refinement.
> Behind that floor sits
> the `DOCTRINE_WORKER`-keyed CLI guard (`src/commands/guard.rs::worker_guard`,
> refusing Write- and Orchestrator-classed verbs) as a defence-in-depth leg behind
> it, not as the trust floor. The import belt was also always weaker than this text
> implies: `classify_import` (`src/worktree/import.rs`) enforces the two hard-coded
> prefix floors `.doctrine/**` and `.claude/**`, plus the `--slice`-scoped
> `undeclared-scope` leg (`Refusal::UndeclaredScope`, `import.rs:136-152`) — three
> rejection grounds, not two. It never enforced the configurable
> `DispatchConfig::worker_forbidden_writes` tail (`.agents/**`, `install/agents/**`,
> `flake.nix`), whose only production reader was the now-deleted `worker_commit` MCP
> tool — so that tail today enforces nothing, a gap carried to `SL-255` as `IDE-051`.
> The historical analysis below is retained for the record; it no longer describes
> the shipped posture.

This ADR is **project-local to doctrine-the-repo** — how doctrine dogfoods the
parallel worktree dispatch defined by ADR-006 inside its own bubblewrap jail. It
is downstream of ADR-006 and prescribes nothing for consuming projects.

It also **discharges ADR-006 D2b** (raw-tree confinement), which D2b explicitly
deferred to "sandbox/harness work (ADR-008)". A generic harness cannot confine a
worker to its worktree (observed: Claude Code creates the worktree but lets the
agent write to main). Doctrine's jail *is* a sandbox, so doctrine can solve here
what the framework layer cannot.

Project-local facts that force the decisions:

- `CARGO_TARGET_DIR=/home/david/.cargo/doctrine-target-jail` is a **single shared
  absolute path** (flake.nix). Two worktrees on different branches sharing it
  cargo-lock-serialize *and* thrash — each branch's source invalidates the
  other's fingerprints.
- `~/.cargo/bin/doctrine` is **read-only** in the jail, so `cargo install` is
  impossible in-jail regardless.
- `CARGO_BIN_EXE` is baked at compile time; e2e tests spawn
  `$CARGO_TARGET_DIR/debug/doctrine` (a shared target gives a stale/foreign
  binary — the known stale-`CARGO_BIN_EXE` spawn-fail).
- justfile recipes are env-driven (`cargo build/test/install`), no hardcoded
  paths.

**Empirical evidence (research §5.1, hardened by SL-050/051 dispatch experience).**
The shared-target hazard is not theoretical — the dispatch work surfaced a
**false-green / false-red cluster** that the per-worktree target (D-B1) is the
clean fix for:

- **Shared-target false-green** — two branches sharing one `CARGO_TARGET_DIR`
  cargo-lock-serialize *and* cross-invalidate fingerprints, so a verify can pass
  against another branch's stale artefacts; the mitigation today is a touch +
  re-run ritual ([[mem.pattern.dispatch.shared-target-false-green-touch-rerun]]).
- **Worktree-removal false-red** — `env!(CARGO_MANIFEST_DIR)`-baked test binaries
  point at a removed worktree's path and spawn-fail until recompiled, a false RED
  ([[mem.pattern.dispatch.worktree-removal-stale-manifest-dir-false-red]]); the
  general stale-`CARGO_BIN_EXE` spawn-fail is the same class
  ([[mem.pattern.testing.stale-cargo-bin-exe]]).
- **Debug-vs-release scale timing** — cliff-test bounds must budget ~10× the
  release probe numbers under a debug build
  ([[mem.pattern.testing.debug-vs-release-scale-timing]]).

**Isolation is a perf / false-green concern, not a trust signal** (SL-056 §3): the
agnostic worker-sole-writer guarantee rides the **disk marker + the `import`
`.doctrine/`-rejection belt**, not the build sandbox. So D-B1 is justified *on its
own merits* (parallelism + correct e2e binaries). (Revised by SL-156 / REV-011:
the original "where a per-worktree target is unavailable — claude shares the
jail-wide target (SL-056 §8) — the §5.1 mitigation rituals stand" caveat is
**resolved**, not mitigated — the claude arm now isolates by construction via the
in-tree target, so the rituals are retired.) *(amended SL-254: there is no separate
"claude arm" any more — every harness is a confined subprocess — but the conclusion
survives the relabelling: the in-tree target isolates every fork by construction.)*

## Decision

- **D-B1 — Per-worktree build target (mechanism revised — SL-156 / REV-011).**

  > **AMENDED — REASONING FALSIFIED, CONCLUSION INTACT (SL-254, 2026-08-14).** The
  > decision stands: each worktree builds into its own in-tree `target/`. Two of the
  > reasons given below no longer hold. First, the original mechanism was rejected as
  > "impossible on the claude arm — no hook can inject env into a spawned worker".
  > The claim about *hooks* may still be true, but its consequence is not: the claude
  > worker is now a subprocess we exec ourselves, so injecting env at spawn is
  > trivial, shipped, and load-bearing — `--setenv DOCTRINE_WORKER 1`
  > (`scripts/spawn-confined.sh:183`) is the *whole* of worker identity (`DEC-207`).
  > What survives of the objection is its POL-002 half, which the shipped shape
  > honours: the platform flake sets no project build env; the project's own spawn
  > script sets the confinement env. Second, "on **both** arms" names a topology that
  > no longer exists — there is one arm.

  Each worktree builds into its own target dir. **Mechanism (revised):** isolation
  comes from **retiring** the shared `CARGO_TARGET_DIR` export so cargo defaults to
  each worktree's own in-tree `<worktree>/target` — *not* a platform-injected
  `…/doctrine-target-jail/wt/<branch>` env set at worker spawn (the original
  mechanism, now superseded: impossible on the claude arm — no hook can inject env
  into a spawned worker — and a POL-002 coupling). The **intent is preserved and
  better served**: real build parallelism, no cross-branch fingerprint thrash,
  correct per-worktree `CARGO_BIN_EXE` — correct by construction on **both** arms
  with no env channel. Cost: one target dir per worktree (disk) plus cold fork
  builds (D-B4 sccache is the deferred lever). See SL-156 design D1–D3; REV-011.

- **D-B2 — No `cargo install` mid-dispatch (standing structural fact).** The flake
  **ro-binds `~/.cargo/bin/doctrine`**, so an in-jail `cargo install` is not a
  policy we choose to avoid — it is **structurally impossible**, full stop.
  Therefore **there is no install race because there is no install**: this is a
  standing property of the jail, not a mitigation that could regress. Workers and
  their tests run the per-worktree **build-target** binary
  ([[mem.pattern.build.jail-target-redirect]]); the ro `~/.cargo/bin/doctrine`
  remains the stable entrypoint.

- **D-B3 — Per-worker bwrap confinement (spike-first; codex/pi-only).**

  > **AMENDED — FALSIFIED, AND INVERTED (SL-254, 2026-08-14).** This decision's
  > central claim now reads backwards, so read the body below as history only.
  > **"codex/pi-only … claude's `Agent` tool is not a subprocess and cannot be
  > wrapped"** — on the shipped path the claude worker *is* a subprocess
  > (`claude -p --output-format stream-json`, `scripts/spawn-confined.sh:220`) and is
  > wrapped exactly like any other harness. No "accident-fenced + prompt-enforced"
  > arm remains; confinement is uniform and mandatory, and the thing D-B3 framed as
  > an enhancement the claude arm could not have is now the floor beneath every
  > harness.
  > **The spike's gating question (OQ-2) is settled** — in-jail userns creation
  > works, the nested confinement landed (`IMP-004` closed), and the macOS analog
  > landed with it (`IMP-045` closed; `src/worktree/jail_prefix.rs` Darwin branch
  > emits a `sandbox-exec` prefix).
  > **The back-out arm is gone.** There is no "back out to D-B1 + the ADR-006 D2a
  > CLI guard" and no reduced-enforcement rung (`DEC-208`): a missing `bwrap` is a
  > **named fail-closed refusal**, taken before any fork is minted
  > (`scripts/spawn-confined.sh:62-64`, `src/worktree/jail.rs::REASON_NO_BWRAP`).
  > D2b is therefore discharged outright, not deferred.
  > **"the marker-primary guard"** names a deleted mechanism. The CLI guard survives
  > but is keyed on `DOCTRINE_WORKER` alone (`DEC-207`,
  > `src/commands/guard.rs::worker_guard`); root resolution and the marker leg are
  > gone.
  > **"recorded symmetrically with the claude `SubagentStart` fail-open back-out"** —
  > `src/worktree/subagent.rs` was deleted whole; there is no `SubagentStart`
  > stamping hook left to be symmetric with.
  > **The mount shape differs too, and NOT in the direction first recorded
  > (corrected SL-254).** The jail does not "rw-mount only its worktree and its
  > target dir, ro everything else". On Linux it is `--ro-bind / /` re-opened by
  > explicit rw binds: the fork worktree (`--bind "$D" "$D"`), **the harness config
  > dir** (`--bind "$CFG_DIR" "$CFG_DIR"`, i.e. `~/.claude` or `~/.pi`), a private
  > `/tmp` tmpfs, and `/dev` (`scripts/spawn-confined.sh:176-183`). On macOS there is
  > no `--ro-bind` at all — an `(allow default)` + `(deny file-write*)` SBPL floor
  > with subpath allows, the config dir arriving as an `--extra-rw`/`RW0` grant
  > (`:159`, `jail.rs:482-486`). D-B1's in-tree target already sits inside the
  > worktree bind. And "it ro-binds the marker only — never
  > `.claude/settings.local.json`" is half-wrong in each half: the marker is gone, but
  > it is **not** true that nothing outside the fork worktree is writable. The
  > harness config dir is a deliberate rw carve-out (`DEC-210` — claude needs it for
  > the subscription credential), so the harness's own permission-grant persistence
  > that this text worried about is in fact writable, and so — the sharp edge — are
  > `~/.claude`'s `settings.json`, hooks, and agent definitions. A confined claude
  > worker can write the orchestrator's harness configuration. The narrowed mount set
  > is the known refinement, deliberately not taken.
  > The historical analysis below is retained for the record; it no longer describes
  > the shipped posture.

  The OS-floor hardening that discharges ADR-006 D2b *where a subprocess exists to
  wrap*: run each
  worker in a **nested bwrap** that **rw-mounts only its worktree and its target dir,
  ro everything else (including main)**, so a worker *physically cannot* write to
  main — OS-enforced, not prompt-enforced. It **ro-binds the marker only — never
  `.claude/settings.local.json`** (which must stay writable for the harness's
  permission-grant persistence, SL-056 §9). This is **codex/pi-only**: claude's
  `Agent` tool is not a subprocess and cannot be wrapped (SL-056 §4c), so its
  worker-sole-writer stays **accident-fenced + prompt-enforced** until a free
  channel or OS confinement lands.
  **The spike's gating question is feasibility, not cost (OQ-2):** can an
  **unprivileged user namespace be created inside the jail** at all? The outer bwrap
  may seccomp-block `clone(CLONE_NEWUSER)`, in which case no amount of budget buys a
  nested bwrap. The one-liner empirical probe is `bwrap --unshare-user --ro-bind /
  / true` run **in-jail** (SL-056 PHASE-12). If userns creation works → land the
  `dispatch-worker` profile. If it is blocked or too costly → **back out to D-B1 +
  the ADR-006 D2a CLI guard** (the marker-primary guard, now the *agnostic* trust
  floor — SL-056 §3/§5) and leave D2b formally deferred, recorded symmetrically with
  the claude SubagentStart fail-open back-out. D-B3 depends on D-B1 (the confined
  worker needs its target dir rw).

- **D-B4 — `sccache` deferred (noted).** A shared compilation cache would offset
  D-B1's per-worktree cold-build disk/time cost. Deferred until cold builds
  actually cause pain; recorded here so the option is not rediscovered.

- **D-B5 — Flake exits the build-env business (revised — SL-156 / REV-011).** The
  flake **retires** the shared `CARGO_TARGET_DIR` export entirely — the removal
  *is* the isolation mechanism (Amendment 2); per-worktree build target is a
  project concern, not a platform-injected env (POL-002 is the forcing function).
  The justfile drops the stale-target rituals (`just rebuild-stale`). The only
  platform-added surface remains the `dispatch-worker` bwrap profile (D-B3).
  *(amended SL-254: the flake adds no `dispatch-worker` profile — the confinement
  prefix is computed by doctrine's own `worktree jail-prefix`
  (`src/worktree/jail.rs`, `jail_prefix.rs`) and applied by
  `scripts/spawn-confined.sh`. So the platform-added surface is now **nil**, which
  is what POL-002 wanted; the decision's direction is confirmed, its residual
  named exception is not.)*

- **D-B6 — Nominated-unjailed orchestrator (added — SL-206 / REV-021).**

  > **AMENDED — FALSIFIED WHOLE (SL-254, 2026-08-14).** Every mechanism named below
  > is deleted; nothing in this decision is live.
  > **Lineage.** D-B6 was authored into this ADR by **REV-021** ("ADR-008:
  > nominated-unjailed orchestrator") out of `SL-206`; SL-254 retires the mechanism
  > it granted. Follow the chain REV-021 → SL-254. REV-021 itself is left untouched
  > as the record of the grant.
  > **What went.** The `SubagentStart(dispatch-orchestrator)` nomination hook and the
  > `PreToolUse(Agent)` spawn-gate lived in `src/worktree/subagent.rs` and
  > `src/worktree/pretooluse.rs`, both **deleted entire**. With them go the
  > PassThrough allowlist and its fixed `$CLAUDE_PROJECT_DIR`-resolved path,
  > `decide()`'s scoped `PassThrough` grant, the privileged / nomination-eligible
  > set, invariants **I1** (one list, every spawn seam) and **I2** (config outside
  > every jail), the `SubagentStop` stale-id hygiene matcher, and the I1 doctor
  > check. `OQ-4` (`Workflow`-seam identity carriage) is moot — the seam it would
  > have gated is gone.
  > **Why the decision itself is moot, not merely its plumbing.** D-B6 was framed as
  > "a deliberate exception to the subagent confinement wall". There is no subagent
  > confinement wall: confinement is now a kernel jail around a spawned *process*,
  > not a hook mediating an in-session agent's tool calls, so there is no wall to
  > except from and no in-session spawn seam to gate.
  > **The three-item ledger.** *(a)* The "reversible escape hatch" was **Mode B**,
  > the confined in-session orchestrator — Mode B is retired entirely (`DEC-217`), so
  > the exit it named does not exist. *(b)* The seam-symmetry standing price is
  > discharged: with no in-session spawn seam left, there is nothing to keep
  > symmetric and no per-harness-release re-payment. *(c)* The O-steered blast radius
  > is **not** dismissed by this amendment. The nomination machinery that bounded the
  > *escalation* direction is gone, but the observation that an unjailed orchestrator
  > consumes attacker-shaped input (the worker's diff) with unjailed reach over the
  > primary tree, history and `.claude/` describes a posture SL-254 did not change.
  > Whether that residual now needs a named bound of its own is a governance question
  > SL-254 does not settle — flagged here, not answered.
  > The historical analysis below is retained for the record.

  The dispatch orchestrator runs **unjailed** (`PassThrough`, RW `.git`) — a deliberate
  exception to the subagent confinement wall, superseding the SL-199 Mode-B posture
  (confined orchestrator, every coord write via server-side MCP). Chosen for
  simplicity of reasoning and lower implementation complexity, **not necessity** —
  a confined orchestrator was proven viable (SL-206 P0 Q2).
  **Mechanism — two halves, one closed loop** (proven P1/P3/P4, 2026-07-06;
  SL-206 `design.md` §5.6):
  1. *Nominate.* A `SubagentStart(dispatch-orchestrator)` hook writes the spawned
     `agent_id` to a PassThrough allowlist at a fixed `$CLAUDE_PROJECT_DIR`-resolved
     path (sync-blocking — lands before the orchestrator's first `PreToolUse`);
     `decide()` grants `PassThrough` scoped to that one id.
  2. *Gate.* A `PreToolUse(Agent)` matcher denies the spawn iff
     `agent_id present ∧ caller ∉ allowlist ∧ subagent_type ∈ privileged-set` —
     the caller id is present exactly when subagent-initiated, so a jailed
     `Agent`-holder cannot spawn an auto-nominated child; escalation closes at the
     source, no arming token.
  **Invariants.** *I1 — one list, every spawn seam:* the gate's privileged deny-set
  IS the nomination-eligible-set, gating every harness spawn seam (`Agent`,
  `Workflow`, any future surface — a new seam defaults to gated, not forgotten);
  checked, not asserted, by a doctor check (Error-severity: nomination ⊄ gate, or a
  registered seam with no matcher). The `Workflow` seam is blanket-denied to any
  caller with a present `agent_id` until OQ-4 proves identity carriage — its
  outcome only decides whether that seam relaxes to the finer identity-gate, never
  whether it is safe. *I2 — config outside every jail:* allowlist + hook config are
  writable only by the main thread; a worker cannot nominate anything. *Fail-safe:*
  every failure mode lands on more confinement — a missed `SubagentStart` leaves
  the orchestrator jailed (visible functional failure, never an escape); a
  `SubagentStop` matcher removes the allowlist entry (stale-id hygiene).
  **Ledger — recorded beyond the grant** (REV-021): (a) the **confined Mode-B
  orchestrator is the reversible escape hatch** — it loses nothing functional
  (import already routes via the shipped MCP); if the seam-symmetry obligation
  proves unmaintainable, revert with no functional loss. (b) **Seam-symmetry is
  the standing price** — I1's duty is permanent while the orchestrator runs
  unjailed, and stays one-time ONLY while conformance-checked; as prose it would
  be re-paid per harness release. (c) **O-steered blast radius, named out loud** —
  P1/P3/P4 bound jailed→orchestrator *escalation* only; they say nothing about a
  *steered* orchestrator, whose primary attacker-shaped input is the worker's diff
  and whose unjailed reach (primary tree, history, `.claude/`) Mode-B's tunnel-set
  bounded. The residual is roughly what the main thread already accepts running
  `/dispatch` by hand, mitigated by the trusted committed def, narrow prompt, and
  structured inputs (diffs + typed receipts, not free-form instructions) — it is
  NOT covered by the escalation proofs.
  Consistency: ADR-006 / CHR-039 — the orchestrator is unconfined *by design*
  (sole writer); nomination relocates the main thread's existing unjailed status
  to a trusted committed def (name unforgeable: `.claude/agents/` is
  worker-unwritable, jailed + R-5) — it invents no new trust. Rule: **grant power
  scales with intent evidence** — type-match alone buys bounded/gated capability
  (worker tier); anything unbounded (`PassThrough`) requires the spawn-gate.

## Consequences

### Positive

- doctrine-the-repo becomes a **reference implementation** of safe parallel
  worktree dispatch, and (if D-B3 lands) of *true* worker confinement — proving
  ADR-006 D2b is solvable wherever a sandbox exists. *(amended SL-254: the
  conditional is discharged — D-B3 landed and is now mandatory on every harness, so
  this reads "and of true worker confinement". The proof is stronger than the claim:
  D2b is solvable wherever a sandbox exists, and where one does not exist doctrine
  refuses to dispatch rather than degrade.)*
- Per-worktree targets (D-B1) make parallel build/test genuinely concurrent
  instead of cargo-lock-serialized, with correct e2e binaries.

### Negative

- Disk grows with concurrent worktrees (N target dirs); a worktree cap or D-B4
  may be needed under disk pressure.
- D-B3's nested bwrap adds plumbing; the spike may fail and force the weaker
  fallback (D-B1 + D2a), leaving D2b deferred. *(amended SL-254 — falsified: the
  spike did not fail. The plumbing was paid for and is now unconditional; there is
  no weaker fallback and D2b is discharged, not deferred. The cost that replaced
  this one differs in kind — where no sandbox exists, dispatch is simply
  unavailable — by named refusal on Linux, by an unnamed exec failure on macOS,
  which has no backend-presence probe (`DEC-208`).)*
- D-B6 buys plain-git convenience for the orchestrator at a **standing
  obligation**: nomination machinery + spawn-gate + `SubagentStop` hygiene + the
  seam-symmetry duty forever (every future harness spawn surface inherits gate
  duty). The Mode-B escape hatch (ledger (a)) is the bounded exit. *(amended
  SL-254 — falsified whole: D-B6 is retired, so neither the standing obligation nor
  the escape hatch exists. Mode B itself was retired entirely by `DEC-217`; the
  obligation is discharged by the disappearance of the seam, not by being met.)*

### Neutral

- Nothing here is exercised until `/dispatch` is implemented and run on doctrine
  itself; this ADR is governance-ahead-of-need so the eventual implementation
  slice inherits the decisions. *(amended SL-254 — no longer true: `/dispatch` is
  implemented and run on doctrine itself, through
  `scripts/spawn-confined.sh <harness>`. This ADR is exercised, not
  governance-ahead-of-need.)*
- Host-vs-jail mount-path separation is preserved: per-worktree dirs nest under
  the existing jail-redirect root. *(amended SL-254 — stale since SL-156 / REV-011:
  there is no jail-redirect root to nest under; each worktree's target is in-tree,
  per D-B1/D-B5 as revised. Noted here in the SL-254 sweep, not falsified by it.)*

## Verification

- D-B1: two parallel worktree builds run without cargo-lock contention, each
  producing a binary its own e2e tests spawn successfully (no stale-`CARGO_BIN_EXE`).
- D-B3 feasibility (OQ-2): the in-jail userns probe `bwrap --unshare-user --ro-bind
  / / true` records a clear land/back-out decision (SL-056 PHASE-12). If landed: a
  worker process, given a write to a path outside its worktree (e.g. main's
  `.doctrine`), is OS-denied, and the confined worker cannot `rm` its ro-bound
  marker. If backed out: D2b's deferral is recorded, never silently dropped.
  *(amended SL-254: OQ-2 is settled — it landed, on every harness, and there is no
  back-out branch left to record. The marker clause names a deleted object
  (`DEC-207`); drop it. The live legs are: a worker's write outside the jail's
  writable set — the fork worktree **plus the harness config dir**, plus scratch and
  device sinks — is kernel-denied (`--ro-bind / /` on Linux; the SBPL
  `(deny file-write*)` floor on macOS); and `bwrap` absent ⇒ the spawn
  refuses **by name** before minting a fork
  (`scripts/spawn-confined.sh:62-64` ≡ `src/worktree/jail.rs::REASON_NO_BWRAP`,
  the two kept in agreement by a checked test rather than a comment — STD-001) —

### N1 — sanctioned `worker_commit` exception to the PreToolUse jail wall (SL-198, 2026-07-04)

> **AMENDED — FALSIFIED, DOUBLY (SL-254, 2026-08-14).** This note is dead at both
> ends: it records `worker_commit` as *the exception to the `PreToolUse` jail wall*,
> and SL-254 deleted **both the exception and the wall it excepted from**.
> **The wall.** `src/worktree/pretooluse.rs` — whose `decide()` gated
> `Bash|Edit|Write` and let `mcp__*` pass through — was deleted **whole**. There is
> no in-session `PreToolUse` mediator, because a worker is no longer an in-session
> agent whose tool calls can be mediated: it is a confined subprocess, and the
> boundary is the kernel's.
> **The exception.** The `mcp__doctrine__worker_commit` MCP tool was deleted
> (`DEC-204`). A worker cannot commit at all now — it hands back an **uncommitted
> working tree** and the orchestrator imports the diff.
> Three consequences worth naming. **(1)** The `mcp__*` passthrough hole this note
> described (RSK-225) is not "narrowed" any more; it is **moot**, there being no
> hook wall for anything to pass through. **(2)** Doctor check #9
> `AgentConformance` survives, but the single token it whitelisted is gone: the
> conformant worker surface is now the plain tool set and **nothing** `mcp__*`
> (`DEC-216`). **(3)** The `worker_forbidden_writes` config key lost its *only*
> production reader with `worker_commit`. `classify_import`
> (`src/worktree/import.rs`) — sometimes described as the surviving replacement —
> never enforced that key: it enforces the two hard-coded prefix floors `.doctrine/**`
> and `.claude/**` plus the `--slice`-scoped `undeclared-scope` leg, so the
> configurable tail (`.agents/**`, `install/agents/**`,
> `flake.nix`) today enforces nothing. That gap is carried to `SL-255` as `IDE-051`,
> to be closed at spawn time by read-only binds rather than by a post-import belt.
> The note is retained for the record; it describes no live mechanism.

The confinement layer this ADR prescribes walls a worker's raw `Bash git commit`
(ro shared `.git`), but the PreToolUse mediator (`pretooluse.rs` `decide()`) only
gates `Bash|Edit|Write` — **`mcp__*` tools already pass through** to the unconfined
harness-child MCP server (RSK-225, witnessed `7bd21f49`). SL-198 turns that
pre-existing passthrough into a **sanctioned, bounded** write path: the jailed worker
self-commits through the one MCP tool `mcp__doctrine__worker_commit`, made safe by a
**deny-by-default conformance lint** (doctor check #9 `AgentConformance`, Error-gated)
that forbids every agent-def any writable `mcp__*` grant except that single token.

This is a **note, not an amendment** (audit RV-247 F-9): it changes **no** decision in
this ADR. `worker_commit` un-jails nothing structurally — it rides a hole that already
existed and the lint **narrows** the tool surface rather than widening it. The formal
ADR-012 REV and ADR-011 D6 amendment for the confined-subagent orchestrator remain
**SL-199** scope. See `SL-198` design §11 (RV-247 reconciliation) and `SL-182`.
