This is the claim that the shaping is finished and the writing can begin, made
by whoever is about to do the writing, on their own behalf.

It looks like a duplicate of the judgement made one stage earlier, and it is
not. That one said the questions asked were enough. This one says the answers
in hand are enough to write from — a different claim, made by a different
party, and either can be true while the other is false. The common error is to
treat this as automatic once the earlier judgement is given, which quietly
deletes the only chance to say *I still do not know enough to write this*.

Claimed prematurely, the drafting does not fail. It fills. Wherever a decision
is missing, plausible text goes in instead, and that is the hardest defect in
a design to find afterwards, because nothing about the result reads as
incomplete.

**Who should claim it.** Inquiry spends a lot of context, and what it settled
now lives in the run's structured record, not only in this conversation.
Drafting wants that record in a different shape than inquiry built it in. If
you conducted the inquiry in this context, offer the user `/handover` before
claiming readiness, so a fresh agent re-enters through `doctrine design resume`
and makes this claim itself. If they decline, or you are already that fresh
agent, carry on.

**What is enough.** This is your own check, not a question for the user: can
you name the decision behind every section you are about to write? If one is
missing, say which and go back to inquiring. If none is, declare it and carry
on.
